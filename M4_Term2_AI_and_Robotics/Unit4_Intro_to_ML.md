### คาบที่ 30: ขั้นตอน Machine Learning (ML Workflow)
- **จุดประสงค์การเรียนรู้:**
  1. อธิบายขั้นตอนหลักของ ML Workflow (ข้อมูล → ฟีเจอร์ → โมเดล → ประเมินผล) ได้ถูกต้อง
  2. ระบุฟีเจอร์ (Features) และป้ายกำกับ (Labels) จากโจทย์ข้อมูลเซนเซอร์หรือภาพได้
- **แนวคิดหลัก:** การสร้าง ML ไม่ใช่แค่กดปุ่มเทรน แต่เป็นกระบวนการต่อเนื่องตั้งแต่การเลือกข้อมูลที่ใช่ สกัดคุณลักษณะ (Features) ฝึกโมเดล และวัดผล
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | เชื่อมโยงข้อมูล `sensor_log.csv` จากคาบ 16 สู่การสร้างโมเดล ML |
  | 5–15 นาที | บรรยาย/สาธิต | อธิบาย 4 ขั้นตอน: Data → Features → Model → Evaluate พร้อมนิยาม Feature & Label |
  | 15–25 นาที | ฝึกปฏิบัติแบบมีผู้ช่วย | ช่วยกันชี้ Feature และ Label จากตารางข้อมูลสภาพอากาศ/เซนเซอร์ |
  | **25–50 นาที (50%)** | **โครงงานปลายคาบ** | ลงมือทำเอง |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** แผนภาพ ML Workflow สำหรับโจทย์เซนเซอร์/หุ่นยนต์ของทีม
  - **โจทย์/สถานการณ์:** ทีมต้องออกแบบกระบวนการสร้างโมเดล ML เพื่อแก้ปัญหา 1 อย่างในโรงเรียน (เช่น ทำนายสภาพอากาศร้อนจัด, จำแนกวัตถุหน้าหุ่นยนต์, หรือตรวจจับท่าทาง)
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** แผนภาพ ML Workflow 1 หน้า ที่ระบุชัดเจนครบทั้ง 4 ขั้น: (1) แหล่งข้อมูลและขนาดตัวอย่าง, (2) รายชื่อ Features & Label, (3) ประเภทโมเดลที่เลือก, (4) วิธีประเมินผล
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. เลือกโจทย์จากเซนเซอร์ที่มี (LDR, DHT, Ultrasonic, IR หรือกล้อง)
    2. กำหนดว่าอะไรคือ **Features** (ค่าอินพุต) และ **Label** (คำตอบที่อยากให้ทาย)
    3. วาดผัง 4 ขั้นตอนเชื่อมต่อกัน พร้อมระบุปัญหาที่อาจเกิดในแต่ละขั้น (เช่น ข้อมูลน้อยไป)
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - ครบทั้ง 4 ขั้นตอนของ ML Workflow (4 คะแนน)
    - ระบุ Features และ Label ได้ถูกต้องและวัดค่าได้จริง (4 คะแนน)
    - สอดคล้องกับโจทย์และอุปกรณ์ที่มี (2 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** โจทย์ "ทำนายความสบายในห้องเรียน": Features = `[temp, humidity, light]` → Label = `สบาย/ร้อนอบอ้าว` → Model = Decision Tree → Evaluate = Accuracy & Confusion Matrix
  - **ตัวเลือกเสริม (Extension):** เพิ่มขั้นตอน Data Cleaning จาก ม.4/1 เข้าไปก่อนขั้นสกัด Features
  - **แนวทางช่วยเหลือ (Scaffold):** แจกกล่องผัง ML Workflow 4 ขั้นตอนเปล่าพร้อมตัวอย่าง 1 ชุด
- **วัสดุ/เครื่องมือที่ต้องเตรียม:** คอมพิวเตอร์, Canva / Google Slides
- **คำถามสะท้อนคิดปิดคาบ:**
  1. ทำไมการเลือก Features ที่ไม่เกี่ยวข้องกับคำตอบ (เช่น สีเสื้อ กับ คะแนนสอบ) ถึงทำให้โมเดลทายมั่ว?
  2. ขั้นตอนไหนใน ML Workflow ที่มักใช้เวลามากที่สุดในงานจริง?

### คาบที่ 31: เก็บและเตรียมข้อมูลเซนเซอร์/ภาพ (3 คลาส)
- **จุดประสงค์การเรียนรู้:**
  1. ออกแบบแผนการเก็บข้อมูล 3 คลาสให้มีความสมดุลและหลากหลายได้
  2. เก็บข้อมูลเซนเซอร์หรือภาพ ติดป้ายกำกับ (Labeling) และจัดเตรียมเป็นชุดข้อมูลพร้อมฝึกสอนได้
- **แนวคิดหลัก:** คุณภาพของโมเดลขึ้นอยู่กับคุณภาพข้อมูล (Data-centric AI) ข้อมูลทั้ง 3 คลาสต้องมีจำนวนใกล้เคียงกันและครอบคลุมสภาพแวดล้อมจริง
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | แสดงตัวอย่างข้อมูลที่คลาสหนึ่งมี 100 แถว อีกคลาสมี 5 แถว (Imbalanced Data) |
  | 5–15 นาที | บรรยาย/สาธิต | สอนวิธีเก็บข้อมูล 3 คลาสจากเซนเซอร์ (บันทึกลง CSV) หรือภาพ (จัดโฟลเดอร์) |
  | 15–20 นาที | เตรียมอุปกรณ์ | เลือกสายข้อมูลที่จะเก็บ (สายเซนเซอร์ CSV หรือ สายภาพ Teachable Machine) |
  | **20–50 นาที (60%)** | **โครงงานปลายคาบ** | ลงมือทำเอง |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** คลังข้อมูล 3 คลาสคุณภาพสูง (3-Class Dataset Builder)
  - **โจทย์/สถานการณ์:** สร้างชุดข้อมูลจริง 3 คลาสสำหรับใช้ฝึกโมเดลในคาบ 32–35 (เลือกได้ 2 แบบ: A. ข้อมูลเซนเซอร์ใน CSV เช่น สภาพแสง/ระยะ/อุณหภูมิ 3 สถานะ, B. ข้อมูลภาพ 3 คลาส เช่น ขยะ 3 ประเภท หรือ ป้ายสัญญาณจราจร 3 แบบ)
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** ชุดข้อมูล 3 คลาสที่ติดป้ายกำกับครบถ้วน (คลาสละ ≥ 20 ตัวอย่าง รวม ≥ 60 ตัวอย่าง) พร้อมสรุปจำนวนต่อคลาสและสภาพแวดล้อมตอนเก็บ
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. กำหนดชื่อ 3 คลาสให้ชัดเจน (เช่น `0_empty`, `1_plastic`, `2_paper` หรือ `dark`, `indoor`, `outdoor`)
    2. เก็บข้อมูลจริงคลาสละ ≥ 20 ตัวอย่าง โดยเปลี่ยนมุม/ระยะ/สภาพแสงเล็กน้อย
    3. ตรวจสอบความสะอาด (ลบข้อมูลที่เบลอหรือค่าเซนเซอร์เพี้ยนทิ้ง)
    4. บันทึกเป็นไฟล์ CSV (สายเซนเซอร์) หรือโฟลเดอร์ภาพที่จัดหมวดแล้ว
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - ครบ 3 คลาสและมีจำนวนตัวอย่าง ≥ 20 ต่อคลาสอย่างสมดุล (4 คะแนน)
    - ติดป้ายกำกับ (Label) ถูกต้องไม่ปะปน (3 คะแนน)
    - ข้อมูลมีความหลากหลายเหมาะกับการฝึกโมเดลจริง (3 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** ไฟล์ `env_3class.csv` มี 60 แถว (คลาสละ 20 แถว) คอลัมน์ `light,temp,dist,label` สะอาดพร้อมใช้ใน scikit-learn
  - **ตัวเลือกเสริม (Extension):** เก็บข้อมูลชุดทดสอบ (Test Set) แยกต่างหากอีกคลาสละ 5 ตัวอย่างไว้รอวัดผลในคาบหน้า
  - **แนวทางช่วยเหลือ (Scaffold):** เตรียมสคริปต์ MicroPython ที่กดปุ่มบนบอร์ดแล้วบันทึกค่าเซนเซอร์ + ชื่อคลาสลง CSV ให้อัตโนมัติ
- **วัสดุ/เครื่องมือที่ต้องเตรียม:** ESP32 + เซนเซอร์ หรือ เว็บแคม, คอมพิวเตอร์
- **คำถามสะท้อนคิดปิดคาบ:**
  1. ถ้าคลาสหนึ่งมี 50 ตัวอย่าง แต่อีกสองคลาสมีแค่ 5 ตัวอย่าง โมเดลจะมีนิสัยการทายอย่างไร?
  2. เราควรเก็บข้อมูลเพิ่มอย่างไรถ้าต้องการให้โมเดลทำงานได้ทั้งตอนเช้าและตอนเย็น?

### คาบที่ 32: Teachable Machine — เทรนโมเดลจำแนกภาพ/เสียง/ท่าทาง
- **จุดประสงค์การเรียนรู้:**
  1. ใช้ชุดข้อมูลที่เตรียมไว้ฝึกสอนโมเดลด้วย Teachable Machine และปรับค่าพารามิเตอร์เบื้องต้นได้
  2. ทดสอบความมั่นใจ (Confidence Score) และวิเคราะห์จุดที่โมเดลยังสับสนได้
- **แนวคิดหลัก:** Teachable Machine ช่วยให้สร้างโมเดลจำแนกภาพ เสียง หรือท่าทางได้โดยไม่ต้องเขียนโค้ดซับซ้อน แต่ต้องทดสอบและปรับปรุงข้อมูลเมื่อความมั่นใจต่ำ
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | นำชุดข้อมูล 3 คลาสจากคาบ 31 มาตรวจสอบความพร้อม |
  | 5–15 นาที | บรรยาย/สาธิต | สาธิตการอัปโหลด/ฝึกโมเดล (ภาพ/เสียง/ท่าทาง) และการอ่านแถบ Confidence % |
  | 15–22 นาที | ฝึกปฏิบัติแบบมีผู้ช่วย | เทรนโมเดลรอบแรกและดูผล Preview ร่วมกัน |
  | **22–50 นาที (56%)** | **โครงงานปลายคาบ** | ลงมือทำเอง |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** โมเดล AI จำแนก 3 คลาสฉบับอัปเกรด (Ready-to-Control Model)
  - **โจทย์/สถานการณ์:** ฝึกโมเดลจากข้อมูลจริงในคาบ 31 (หรือเพิ่มคลาสเสียง/ท่าทาง) แล้วทดสอบจนได้ความแม่นยำและความมั่นใจสูงพร้อมส่งออก (Export) ไปคุมอุปกรณ์ในคาบ 33
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** ลิงก์/ไฟล์ Export โมเดล Teachable Machine (เช่น TensorFlow.js / Keras) ที่ทดสอบกับสถานการณ์ใหม่ 9 ครั้งทายถูก ≥ 7 ครั้ง (Confidence ≥ 80%)
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. นำเข้าชุดข้อมูล 3 คลาส (หรือบันทึกเสียง/ท่าทาง Pose 3 คลาส)
    2. กด Train Model รอบที่ 1
    3. ทดสอบ 9 ครั้ง (คลาสละ 3 ครั้งในสภาพแวดล้อมใหม่) และจดบันทึกครั้งที่ทายผิด
    4. เพิ่มข้อมูลในมุมที่โมเดลทายผิดแล้วกด Train รอบที่ 2 จนแม่นยำขึ้น แล้วกด Export Model เตรียมไว้
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - เทรนโมเดลครบ 3 คลาสและ Export โมเดลสำเร็จ (3 คะแนน)
    - ทดสอบรอบปรับปรุงทายถูก ≥ 7 ใน 9 ครั้ง (4 คะแนน)
    - มีบันทึกเปรียบเทียบความแม่นยำรอบที่ 1 vs รอบที่ 2 (3 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** รอบ 1 ทายขวดน้ำใสผิดเป็นพื้นหลัง → เพิ่มภาพขวดน้ำในมุมสะท้อนแสงอีก 10 ภาพ → รอบ 2 ทายถูก 8/9 ครั้ง
  - **ตัวเลือกเสริม (Extension):** ลองปรับค่า Epochs / Learning Rate ในเมนู Advanced แล้วสังเกตผล
  - **แนวทางช่วยเหลือ (Scaffold):** เตรียมแบบฟอร์มบันทึกผลการทดสอบ 9 ช่องและวิธี Export โมเดลเป็นไฟล์/ลิงก์
- **วัสดุ/เครื่องมือที่ต้องเตรียม:** คอมพิวเตอร์, อินเทอร์เน็ต, เว็บแคม/ไมโครโฟน, Teachable Machine
- **คำถามสะท้อนคิดปิดคาบ:**
  1. การเพิ่มข้อมูลตรงจุดที่โมเดลทายผิดในรอบแรก ช่วยพัฒนาโมเดลได้ดีกว่าการสุ่มถ่ายเพิ่มอย่างไร?
  2. ค่า Confidence 55% กับ 98% บอกอะไรเราในการนำไปสั่งงานหุ่นยนต์?

### คาบที่ 33: ส่งผล Teachable Machine ไปควบคุมอุปกรณ์จริง
- **จุดประสงค์การเรียนรู้:**
  1. เชื่อมต่อผลลัพธ์การทำนายจากโมเดล Teachable Machine (บนคอมพิวเตอร์/เว็บ) ไปยัง ESP32 ผ่าน Serial (USB) หรือ Web Serial/HTTP ได้
  2. สร้างระบบสั่งงาน LED เซอร์โว หรือหุ่นยนต์ด้วย AI จำแนกภาพ/ท่าทาง/เสียงได้จริง
- **แนวคิดหลัก:** AI จะเกิดประโยชน์สูงสุดเมื่อเชื่อมต่อการตัดสินใจ (Think) เข้ากับการลงมือทำทางกายภาพ (Act) บนไมโครคอนโทรลเลอร์
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | ทบทวนโมเดล 3 คลาสจากคาบ 32 |
  | 5–15 นาที | บรรยาย/สาธิต | สาธิตสะพานเชื่อมต่อ: Python/Web รับภาพ → ทำนายคลาส → ส่งตัวอักษร `'1'`, `'2'`, `'3'` ผ่าน Serial ไป ESP32 |
  | 15–22 นาที | ฝึกปฏิบัติแบบมีผู้ช่วย | ทดสอบส่งข้อความ `'1'` จาก PC ไปเปิด LED บน ESP32 (ปิด Thonny ก่อนเปิด Serial บน Python/Web) |
  | **22–50 นาที (56%)** | **โครงงานปลายคาบ** | ลงมือทำเอง |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** อุปกรณ์สั่งการด้วย AI (AI-Controlled Smart Device)
  - **โจทย์/สถานการณ์:** เปลี่ยนโมเดล Teachable Machine จากคาบ 32 ให้สั่งงานโลกจริงได้ (เช่น ชูนิ้ว 1-2-3 เปิดไฟ 3 สี, หรือ แยกขยะพลาสติก/กระดาษให้เซอร์โวปัดไปคนละทาง, หรือพูดคำสั่งควบคุมรถ)
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** ระบบที่ทำงานร่วมกันระหว่างโมเดล Teachable Machine บน PC กับ ESP32 + อุปกรณ์ปลายทาง (LED / Servo / มอเตอร์) สั่งงานครบทั้ง 3 คลาสได้จริง
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. เขียนโค้ดบน ESP32 (`main.py`) รอรับคำสั่งจาก Serial/UART (`sys.stdin.read(1)` หรือ `input()`) แล้วสั่งเปิด LED/หมุนเซอร์โวตามตัวอักษรที่ได้รับ

### คาบที่ 36: วัดผลโมเดล, Overfitting และ Confusion Matrix
- **จุดประสงค์การเรียนรู้:**
  1. อธิบายอาการ Overfitting และ Underfitting โดยเทียบคะแนน Train Accuracy กับ Test Accuracy ได้
  2. สร้างและอ่านค่าจากตาราง Confusion Matrix เพื่อระบุว่าโมเดลมักทายสับสนระหว่างคลาสใดได้
- **แนวคิดหลัก:** Accuracy ตัวเดียวอาจหลอกเราได้ Confusion Matrix ช่วยให้เห็นจุดที่โมเดลทายผิดบ่อย และการเทียบคะแนน Train vs Test ช่วยจับอาการ "ท่องจำข้อสอบ" (Overfitting)
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | ยกตัวอย่างนักเรียนที่ได้คะแนนแบบฝึกหัด 100% แต่สอบจริงได้ 50% (Overfitting!) |
  | 5–15 นาที | บรรยาย/สาธิต | สอนดู Train vs Test Score, `max_depth` ใน Decision Tree, และ `confusion_matrix` |
  | 15–25 นาที | ฝึกปฏิบัติแบบมีผู้ช่วย | พิมพ์ `confusion_matrix(y_test, y_pred)` และอ่านตัวเลขแนวทแยง |
  | **25–50 นาที (50%)** | **โครงงานปลายคาบ** | ลงมือทำเอง |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** ใบรายงานวิเคราะห์สุขภาพโมเดล (Model Diagnostic Report)
  - **โจทย์/สถานการณ์:** ตรวจสอบโมเดลจากคาบ 34–35 ว่ากำลัง "ท่องจำข้อมูล (Overfit)" อยู่หรือไม่ และวิเคราะห์ว่ามักทายคลาสไหนผิดพลาดที่สุดเพื่อปรับปรุงให้ดีขึ้น
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** Colab Notebook + ใบงานวิเคราะห์ผล 1 หน้า แสดง (1) กราฟ/ตารางเปรียบเทียบ Train vs Test Accuracy เมื่อปรับ `max_depth`, (2) ภาพ Confusion Matrix, (3) ข้อสรุปจุดอ่อนและวิธีแก้
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. ทดลองเปลี่ยน `max_depth` ของ Decision Tree (เช่น `2, 5, None`) แล้วปริ้นท์ทั้ง `Train Accuracy` และ `Test Accuracy`
    2. สังเกตจุดที่ Train สูงมาก (เช่น 100%) แต่ Test ตกลง (อาการ Overfit)
    3. สร้างและแสดงผล `ConfusionMatrixDisplay.from_predictions(y_test, y_pred)`
    4. เขียนวิเคราะห์ในใบงานว่าโมเดลทายคลาสไหนผิดเป็นคลาสไหน และควรเก็บข้อมูลเพิ่มอย่างไร
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - ตรวจจับอาการ Overfitting จากการเทียบ Train vs Test ได้ถูกต้อง (4 คะแนน)
    - สร้างและอ่านค่า Confusion Matrix ได้ถูกต้อง (4 คะแนน)
    - เสนอแนวทางปรับปรุงโมเดลได้ตรงจุด (2 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** ระบุได้ว่า `max_depth=None` เกิด Overfit (Train 100%, Test 78%) แต่ `max_depth=3` สมดุลกว่า (Train 90%, Test 89%) และ Confusion Matrix ชี้ว่าคลาส `indoor` มักถูกทายผิดเป็น `outdoor`
  - **ตัวเลือกเสริม (Extension):** ปริ้นท์ `classification_report` เพื่อดูค่า Precision และ Recall เบื้องต้น
