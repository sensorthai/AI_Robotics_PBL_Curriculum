# ม.5 ภาคเรียนที่ 2: AIoT & Smart Systems (40 คาบ)

**คำอธิบายรายวิชา:** ระบบอัจฉริยะและการเชื่อมต่ออุปกรณ์  
**เครื่องมือ/อุปกรณ์:** ESP32-S3-S3 DevKitC-1 N16R8, Capacitive Soil Moisture, DHT22/AM2302, Water Level Sensor, Rain Sensor, 2-Channel Relay, DC Water Pump (5V–12V), OLED I2C, 12V DC Power Supply, ถังทดลอง+สายยาง, Waterproof Enclosure, Wi-Fi 6 AP (IoT VLAN), AI Server (Docker: Mosquitto MQTT, Node-RED/Grafana, PyTorch), NAS Storage, Bambu Lab A1 Mini (3D Printer)

## ตารางสรุปภาพรวม 40 คาบ

| คาบที่ | ชื่อคาบ | แนวคิดหลัก | โครงงานปลายคาบ |
|---|---|---|---|
| 1 | สถาปัตยกรรม IoT และทบทวน ESP32-S3 | 4 ชั้น IoT (Device–Network–Cloud–App) | ผังระบบ IoT 4 ชั้นสำหรับโจทย์ห้องเรียน/ฟาร์ม |
| 2 | เชื่อมต่อ Wi-Fi และส่งค่าเซนเซอร์ผ่าน HTTP | `network.WLAN`, HTTP GET/POST, API | ESP32-S3 เชื่อม Wi-Fi ส่งค่าอุณหภูมิขึ้นเว็บ/เซิร์ฟเวอร์ |
| 3 | MQTT พื้นฐาน: Broker, Topic และ Publish | โปรโตคอล Publish/Subscribe บน MQTT | ESP32-S3 ส่งค่าเซนเซอร์ (Publish) เข้า MQTT Broker |
| 4 | MQTT ขั้นสูง: Subscribe และสื่อสารสองทาง | การรับข้อความ (Subscribe) และ Callback | ระบบสื่อสารสองทาง Publish–Subscribe ข้ามอุปกรณ์ |
| 5 | แดชบอร์ดแสดงผลและสั่งงานย้อนกลับ | Node-RED / Grafana (บน Docker AI Server) แสดงกราฟและปุ่มควบคุม | แดชบอร์ดเว็บแสดงค่าเซนเซอร์และเปิด-ปิดไฟ ESP32-S3 |
| 6 | ความปลอดภัย IoT เบื้องต้นและทดสอบย่อย | รหัสผ่าน/Token, การไม่ฮาร์ดโค้ดรหัส, TLS | ไฟล์ `secrets.py` + เช็กลิสต์ความปลอดภัย & ทดสอบย่อย |
| 7 | AIoT: Edge AI เทียบกับ Cloud AI | การประมวลผลที่อุปกรณ์ vs บนคลาวด์ | ตารางวิเคราะห์เลือก Edge/Cloud สำหรับ 4 สถานการณ์ |
| 8 | เก็บข้อมูลเซนเซอร์ต่อเนื่องพร้อม Timestamp (ขั้น 1) | การประทับเวลา (NTP/Timestamp) และความถี่สุ่ม | สคริปต์รับข้อมูล MQTT พร้อมเวลาลงไฟล์/ฐานข้อมูล |
| 9 | จัดเก็บชุดข้อมูลอนุกรมเวลาของทีม (ขั้น 2) | การสะสมข้อมูลจริงและตรวจสอบความครบถ้วน | ชุดข้อมูล Time-Series CSV ของทีม (≥ 100 แถว) |
| 10 | แสดงผลข้อมูลอนุกรมเวลา (Time-Series Dashboard) | กราฟเส้นตามเวลาและแนวโน้มการเปลี่ยนแปลง | แดชบอร์ดกราฟอนุกรมเวลาพร้อมวิเคราะห์แนวโน้ม |
| 11 | สร้างกฎอัตโนมัติ (Automation Rules) บนแดชบอร์ด | เงื่อนไขอัตโนมัติ (เช่น ความชื้นต่ำ → รดน้ำ) | ระบบกฎอัตโนมัติสั่งงานรีเลย์/LED เมื่อเซนเซอร์ถึงเกณฑ์ |
| 12 | เชื่อมต่ออุปกรณ์กับโมเดล AI บนเซิร์ฟเวอร์ (ขั้น 1) | ส่งข้อมูล/ภาพจากอุปกรณ์ผ่าน HTTP/MQTT เข้า Python | API/Bridge รับค่าจากอุปกรณ์ส่งให้โมเดลทำนาย |
| 13 | รับผลทำนายกลับจากโมเดลและตอบสนอง (ขั้น 2) | Round-trip Inference และแสดงผลกลับที่อุปกรณ์ | ระบบกล้อง/เซนเซอร์ที่ส่งข้อมูลเข้าโมเดลแล้วได้คำตอบกลับ |
| 14 | Edge AI: โมเดลเล็กบนอุปกรณ์หรือเครื่องใกล้ตัว | TinyML / PyTorch Edge/Quantized / โมเดลรันออฟไลน์ใกล้อุปกรณ์ | สคริปต์รันโมเดลขนาดเล็กแบบ Local/Edge |
| 15 | วัดเทียบความเร็ว Edge AI vs Cloud AI | Latency, Bandwidth, และความเป็นส่วนตัว | ตาราง Benchmark เวลาตอบสนอง Edge vs Cloud |
| 16 | สั่งอุปกรณ์ปลายทาง (รีเลย์/ปั๊ม/พัดลม) ด้วย AI | การขับโหลดกำลังสูงผ่านรีเลย์อย่างปลอดภัย | วงจรรีเลย์ + ปั๊ม/พัดลมที่รับคำสั่งจาก AI ได้ |
| 17 | กลไกความปลอดภัย Fail-Safe สำหรับระบบอัตโนมัติ | Max Runtime, Watchdog, Fallback เมื่อเน็ต/AI หลุด | ระบบควบคุมปั๊ม/พัดลมที่มี Fail-Safe ทำงานได้จริง |
| 18 | ทดสอบปฏิบัติ AIoT ครบวงจร | Sense → Network → AI Think → Fail-Safe Act | ต้นแบบระบบรับรู้-ตัดสินใจ-ทำงานครบวงจร |
| 19 | โจทย์ ML กับข้อมูลเซนเซอร์ (ทำนาย/จำแนก/ผิดปกติ) | การเลือกโจทย์ Time-Series ML ให้เหมาะกับงาน | ใบกำหนดโจทย์ Applied ML ของทีมจากข้อมูลเซนเซอร์ |
| 20 | เตรียมข้อมูลอนุกรมเวลา: ทำความสะอาดข้อมูลเซนเซอร์ | Missing values, Noise smoothing (Rolling Mean) | สคริปต์ทำความสะอาดข้อมูลเซนเซอร์ด้วย `pandas` |
| 21 | สร้างหน้าต่างเวลาและฟีเจอร์ (Windowing & Features) | Lag Features, Rolling Stats สำหรับข้อมูลตามเวลา | ชุดข้อมูลพร้อมฟีเจอร์ (Feature Matrix) สำหรับเทรน ML |
| 22 | สร้างโมเดลทำนายอนุกรมเวลา (ขั้น 1: Baseline) | Regression/Tree ทำนายความชื้นดิน/ความต้องการน้ำ | โมเดลทำนายค่าล่วงหน้าเวอร์ชันแรก + ค่า MAE |
| 23 | ปรับจูนและทดสอบโมเดลทำนาย (ขั้น 2) | การทดสอบข้ามช่วงเวลา (Time-based Split) | โมเดลทำนายฉบับปรับปรุงพร้อมกราฟค่าจริง vs ค่าทำนาย |
| 24 | ตรวจจับความผิดปกติด้วยเกณฑ์สถิติและ Isolation Forest | Anomaly Detection (Z-score / Isolation Forest) | สคริปต์ตรวจจับค่าผิดปกติของเซนเซอร์ด้วย Isolation Forest |
| 25 | เชื่อมต่อระบบแจ้งเตือนความผิดปกติผ่านแดชบอร์ด | Alert Pipeline เมื่อโมเดลพบ Anomaly | ระบบแจ้งเตือนอัตโนมัติบนแดชบอร์ดเมื่อเซนเซอร์ผิดปกติ |
| 26 | ประเมินโมเดลกับข้อมูลจริงและสรุปข้อจำกัด | Drift, ความคลาดเคลื่อนภาคสนาม และข้อจำกัด | รายงานประเมินผลโมเดลกับข้อมูลจริงในห้อง |
| 27 | ออกแบบระบบ Smart System (Block Diagram & BOM) | สถาปัตยกรรมระบบ รายการอุปกรณ์ งบประมาณ ผังข้อมูล | เอกสารออกแบบระบบ 1 ฉบับพร้อม Block Diagram |
| 28 | ประกอบฮาร์ดแวร์และเดินสายอย่างเป็นระบบ (ขั้น 1) | การวางเลย์เอาต์ บอร์ด เซนเซอร์ และรีเลย์ | ชุดฮาร์ดแวร์ที่ประกอบและเดินสายเรียบร้อย |
| 29 | ติดตั้งกล่องหุ้มและความปลอดภัยไฟฟ้า (ขั้น 2) | การแยกส่วนเปียก-แห้ง ฉนวน และการยึดสาย | ชุดฮาร์ดแวร์ในกล่องหุ้มที่ปลอดภัยพร้อมใช้งาน |
| 30 | เชื่อมซอฟต์แวร์ End-to-End: เซนเซอร์ → MQTT → แดชบอร์ด | Data Flow จากฮาร์ดแวร์สู่หน้าจอแสดงผล | ระบบส่งข้อมูลจากฮาร์ดแวร์ขึ้นแดชบอร์ดแบบเรียลไทม์ |
| 31 | เชื่อมซอฟต์แวร์ครบวงจร: เพิ่มโมเดล AI และสั่งควบคุม | ปิดลูป AI → MQTT → รีเลย์/ตัวขับ | ระบบเชื่อมต่อครบทุกชั้น (Sensor → AI → Actuator) |
| 32 | ทดสอบระบบด้วย Test Cases (ปกติและผิดปกติ) | การออกแบบ Test Cases ครอบคลุมกรณีล้มเหลว | ตารางผลทดสอบ (Test Report) ≥ 5 กรณี |
| 33 | เพิ่มความเสถียร: Auto-Reconnect และ Watchdog | การกู้คืนการเชื่อมต่อ Wi-Fi/MQTT อัตโนมัติ | โค้ด ESP32-S3 ที่รันต่อเนื่องและต่อเน็ตใหม่เองได้ |
| 34 | จัดทำเอกสารระบบ: คู่มือใช้งานและแผนผัง 1 หน้า | System Documentation สำหรับผู้ใช้และผู้ดูแล | คู่มือระบบ 1 หน้าพร้อมแผนผังและวิธีแก้เบื้องต้น |
| 35 | เลือกโจทย์ Mini Project และกำหนดเกณฑ์สำเร็จ | Smart Farm / Smart Classroom / Smart Environment | ใบโครงงาน Mini Project + เกณฑ์สำเร็จ |
| 36 | สร้างต้นแบบ Mini Project ระยะที่ 1 (ฮาร์ดแวร์ + เชื่อมต่อ) | ประกอบวงจรจริงและเชื่อมต่อ MQTT/Dashboard (CP1) | ต้นแบบฮาร์ดแวร์ส่งข้อมูลขึ้นแดชบอร์ดได้ (CP1) |
| 37 | สร้างต้นแบบ Mini Project ระยะที่ 2 (ผสาน AI + ควบคุม) | ใส่โมเดล ML/กฎอัตโนมัติและสั่งงานรีเลย์ | ระบบที่ตัดสินใจและสั่งงานอัตโนมัติได้ |
| 38 | ปรับปรุงต้นแบบ Mini Project และ Fail-Safe (CP2) | จูนความเสถียร Reconnect และ Fail-Safe (CP2) | ต้นแบบระบบครบวงจรที่ผ่าน Checkpoint 2 |
| 39 | ทดสอบกับผู้ใช้จริง (เพื่อน/ครู) และปรับปรุงตามฟีดแบ็ก | Usability Testing และเก็บข้อเสนอแนะจริง | บันทึกผลทดสอบกับผู้ใช้จริง + รายการปรับแก้ |
| 40 | Demo Day: นำเสนอสาธิตระบบอัจฉริยะและประเมินผล | การสาธิตสดระบบ AIoT ครบวงจร | เดโมระบบ Smart System 4 นาที + แบบประเมิน |

## โครงงานรวบยอดประจำภาคเรียน
**ระบบ Smart System ครบวงจร** (เลือก 1 ด้าน: Smart Farm, Smart Classroom หรือ Smart Environment) ที่ประกอบจาก:
- โครงข่าย **Wi-Fi, HTTP, MQTT และ Dashboard** จาก **Unit 1 (คาบ 1–6)**
- ระบบ **AIoT (Edge/Cloud), รีเลย์ควบคุมปั๊ม/พัดลม และ Fail-Safe** จาก **Unit 2 (คาบ 7–18)**
- โมเดล **Applied ML ทำนายอนุกรมเวลาและตรวจจับความผิดปกติ** จาก **Unit 3 (คาบ 19–26)**
- การ **ประกอบฮาร์ดแวร์ในกล่องหุ้ม, End-to-End Integration, Reconnect/Watchdog และคู่มือ** จาก **Unit 4 (คาบ 27–34)** สู่ **Mini Project (คาบ 35–40)**
