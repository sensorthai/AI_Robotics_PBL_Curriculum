### คาบที่ 1: สถาปัตยกรรม IoT 4 ชั้น และทบทวน ESP32-S3
- **จุดประสงค์การเรียนรู้:**
  1. อธิบายสถาปัตยกรรมระบบ IoT ทั้ง 4 ชั้น (อุปกรณ์/เซนเซอร์ – เครือข่าย – คลาวด์/เซิร์ฟเวอร์ – แอป/แดชบอร์ด) ได้
  2. ทบทวนการใช้งานบอร์ด ESP32-S3-S3 DevKitC-1 N16R8 กับ MicroPython และวางแผนการไหลของข้อมูลในระบบ IoT ได้
- **แนวคิดหลัก:** ระบบ IoT ไม่ได้จบแค่ที่บอร์ด ESP32-S3-S3 DevKitC-1 N16R8 แต่ประกอบด้วย 4 ชั้นที่ส่งข้อมูลต่อเนื่องกันตั้งแต่ฮาร์ดแวร์ภาคสนามจนถึงหน้าจอผู้ใช้
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | เชื่อมโยง ESP32-S3 (ม.4/2) และ AI (ม.5/1) สู่ AIoT ในเทอมนี้ |
  | 5–15 นาที | บรรยาย/สาธิต | อธิบายสถาปัตยกรรม IoT 4 ชั้น พร้อมตัวอย่างจริง (สมาร์ตฟาร์ม/สมาร์ตโฮม) |
  | 15–25 นาที | ฝึกปฏิบัติแบบมีผู้ช่วย | ต่อ ESP32-S3 กับคอมพิวเตอร์ทดสอบรัน MicroPython เช็กโมดูล `network` ที่มีในบอร์ด |
  | **25–50 นาที (50%)** | **โครงงานปลายคาบ** | ลงมือทำเอง |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** พิมพ์เขียวสถาปัตยกรรม IoT 4 ชั้น (IoT Architecture Blueprint)
  - **โจทย์/สถานการณ์:** คู่ปฏิบัติการต้องออกแบบผังระบบ IoT 1 ระบบที่แก้ปัญหาในโรงเรียน (เช่น รดน้ำแปลงเกษตร, คุมพัดลมห้องเรียน, ตรวจคุณภาพอากาศ) ให้เห็นครบทั้ง 4 ชั้น
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** แผ่นภาพผังระบบ IoT 4 ชั้น (วาดใน โปรแกรมออกแบบออฟไลน์ (Draw.io/LibreOffice Impress)/Slides/Draw.io) ระบุชัดเจนว่าแต่ละชั้นใช้อุปกรณ์/โปรโตคอล/ซอฟต์แวร์ใด และข้อมูลไหลไป-กลับอย่างไร + ภาพยืนยัน ESP32-S3 พร้อมใช้งาน MicroPython
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. เลือกสถานการณ์ IoT 1 เรื่อง (Smart Farm / Classroom / Environment)
    2. วาดกล่อง 4 ชั้น: Device (ESP32-S3-S3 + เซนเซอร์/รีเลย์อะไร) → Network (Wi-Fi / HTTP / MQTT) → Cloud/Broker → App/Dashboard
    3. ลากลูกศรแสดงทิศทางข้อมูลขึ้น (Telemetry) และคำสั่งลง (Control)
    4. ทดสอบเชื่อม ESP32-S3 กับ Thonny IDE เพื่อยืนยันความพร้อมของบอร์ด
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - ครบทั้ง 4 ชั้นของสถาปัตยกรรม IoT และระบุอุปกรณ์/โปรโตคอลถูกต้อง (5 คะแนน)
    - แสดงทิศทางการไหลของข้อมูลและการสั่งงานย้อนกลับชัดเจน (3 คะแนน)
    - บอร์ด ESP32-S3-S3 DevKitC-1 N16R8 พร้อมใช้งาน MicroPython (2 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** ผัง "Smart Plant" ชี้ชัด: Device (ESP32-S3-S3 + Soil Moisture + Relay/Pump) → Network (Wi-Fi + MQTT) → Cloud (Mosquitto + Node-RED) → App (Dashboard มือถือ)
  - **ตัวเลือกเสริม (Extension):** ระบุแหล่งจ่ายไฟและความถี่ในการส่งข้อมูลของอุปกรณ์ในผัง
  - **แนวทางช่วยเหลือ (Scaffold):** แจกเทมเพลตผัง 4 ชั้นเปล่าพร้อมไอคอนอุปกรณ์ให้ลากวาง
- **วัสดุ/เครื่องมือที่ต้องเตรียม:** ESP32-S3, สาย USB, คอมพิวเตอร์, โปรแกรมออกแบบออฟไลน์ (Draw.io/LibreOffice Impress)/Slides
- **คำถามสะท้อนคิดปิดคาบ:**

  2. ความแตกต่างระหว่างโปรเจกต์ ESP32-S3 ใน ม.4/2 กับระบบ IoT ใน ม.5/2 คืออะไร?

### คาบที่ 2: เชื่อมต่อ Wi-Fi และส่งค่าเซนเซอร์ผ่าน HTTP
- **จุดประสงค์การเรียนรู้:**
  1. เขียนโค้ด MicroPython เชื่อมต่อ ESP32-S3 เข้ากับเครือข่าย Wi-Fi และตรวจสอบ IP Address ได้
  2. ส่งค่าเซนเซอร์จาก ESP32-S3 ขึ้นเว็บ/เซิร์ฟเวอร์ผ่านโปรโตคอล HTTP (`urequests`) ได้
- **แนวคิดหลัก:** HTTP ทำงานแบบ Request–Response (ผู้รับต้องถามหรือส่งคำขอไปที่ URL) เป็นวิธีพื้นฐานที่ ESP32-S3 ใช้ส่งข้อมูลขึ้นคลาวด์หรือเว็บเซิร์ฟเวอร์
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | อธิบายหลักการ Request–Response ของ HTTP |
  | 5–15 นาที | บรรยาย/สาธิต | สาธิต `network.WLAN(network.STA_IF)` ต่อ Wi-Fi 2.4 GHz และใช้ `urequests.get()` / `.post()` |
  | 15–25 นาที | ฝึกปฏิบัติแบบมีผู้ช่วย | ต่อ ESP32-S3 เข้า Wi-Fi ห้องเรียน (2.4 GHz) และพิมพ์ IP Address สำเร็จ |
  | **25–50 นาที (50%)** | **โครงงานปลายคาบ** | ลงมือทำเอง |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** สถานีส่งอุณหภูมิขึ้นเว็บด้วย HTTP (HTTP Weather Node)
  - **โจทย์/สถานการณ์:** ต่อเซนเซอร์ (เช่น DHT22 / AM2302 หรือ LDR) เข้ากับ ESP32-S3 แล้วส่งค่าที่อ่านได้ขึ้นเว็บเซิร์ฟเวอร์/บริการคลาวด์ (เช่น ThingSpeak / Webhook.site / Local Python Flask Server `[เสริม]`) ทุก ๆ 15 วินาที
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** วงจร ESP32-S3-S3 + เซนเซอร์ + โค้ด MicroPython ที่ต่อ Wi-Fi สำเร็จและส่งค่าขึ้นเว็บ/เซิร์ฟเวอร์ได้จริง พร้อมภาพแคปหน้าจอเว็บที่ได้รับข้อมูลจริงจากบอร์ด
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. ต่อเซนเซอร์ DHT (หรือ LDR) เข้ากับ ESP32-S3 (ระวังขา ADC1 เมื่อเปิด Wi-Fi บน ESP32-S3!)
    2. เขียนฟังก์ชัน `connect_wifi(ssid, password)` รอจน `wlan.isconnected()` เป็น True
    3. อ่านค่าเซนเซอร์แล้วส่งด้วย `urequests.get(f"{url}?temp={t}&hum={h}")` (อย่าลืม `res.close()` เพื่อคืนหน่วยความจำ!)
    4. เปิดหน้าเว็บปลายทางดูข้อมูลจริงที่ถูกส่งเข้ามา
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - ESP32-S3 เชื่อมต่อ Wi-Fi 2.4 GHz สำเร็จ (3 คะแนน)
    - ส่งค่าเซนเซอร์จริงผ่าน HTTP และเห็นข้อมูลบนเว็บปลายทาง (5 คะแนน)
    - มี `res.close()` และหน่วงเวลาเหมาะสมไม่ยิงถี่เกินไป (2 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** หน้าเว็บ ThingSpeak/Webhook แสดงค่า `temp=28.5, hum=60` อัปเดตต่อเนื่องจาก ESP32-S3 ของทีม
  - **ตัวเลือกเสริม (Extension):** ส่งข้อมูลในรูปแบบ JSON ผ่าน `urequests.post(..., json=data)`
  - **แนวทางช่วยเหลือ (Scaffold):** เตรียมโค้ด `connect_wifi()` และเตือนข้อจำกัด ESP32-S3 (รองรับเฉพาะ Wi-Fi 2.4 GHz และห้ามใช้ขา ADC2 ตอนเปิด Wi-Fi)
- **วัสดุ/เครื่องมือที่ต้องเตรียม:** ESP32-S3, เซนเซอร์ DHT/LDR, Wi-Fi 2.4 GHz, คอมพิวเตอร์
- **คำถามสะท้อนคิดปิดคาบ:**
  1. ทำไมเวลาใช้ Wi-Fi บน ESP32-S3 เราจึงไม่ควรใช้ขา ADC2 (เช่น GPIO 4, 12, 14) อ่านค่า Analog?
  2. ข้อจำกัดของ HTTP คืออะไรหากเราต้องการส่งข้อมูลถี่ ๆ หรือสั่งงานจากเว็บลงมาที่ ESP32-S3 แบบทันทีทันใด?

### คาบที่ 3: MQTT พื้นฐาน — Broker, Topic และ Publish
- **จุดประสงค์การเรียนรู้:**
  1. อธิบายสถาปัตยกรรม Publish/Subscribe ของโปรโตคอล MQTT (Broker, Client, Topic, Payload) ได้
  2. เชื่อมต่อ ESP32-S3 เข้ากับ MQTT Broker และส่ง (Publish) ข้อมูลเซนเซอร์เป็น JSON ได้
- **แนวคิดหลัก:** MQTT เป็นโปรโตคอลมาตรฐานของ IoT ที่เบามาก ใช้แนวคิด "ส่งเข้าหัวข้อ (Publish to Topic)" ผ่านตัวกลางที่เรียกว่า Broker ทำให้ส่งข้อมูลเร็วและประหยัดแบนด์วิดท์กว่า HTTP
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | เทียบ HTTP (โทรไปถาม) กับ MQTT (กดติดตามช่อง YouTube/Topic) |
  | 5–15 นาที | บรรยาย/สาธิต | อธิบาย Broker, Topic (เช่น `room1/teamA/sensor`), ไลบรารี `umqtt.simple` |
  | 15–25 นาที | ฝึกปฏิบัติแบบมีผู้ช่วย | ใช้โปรแกรม MQTT Explorer / เว็บ Client บนคอมพิวเตอร์ลอง Publish ข้อความเข้า Broker |
  | **25–50 นาที (50%)** | **โครงงานปลายคาบ** | ลงมือทำเอง |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** เครื่องส่งสัญญาณเซนเซอร์ผ่าน MQTT (MQTT Telemetry Publisher)
  - **โจทย์/สถานการณ์:** ส่งข้อมูลเซนเซอร์ (อุณหภูมิ/ความชื้น/แสง) จาก ESP32-S3 ไปยัง MQTT Broker ประจำห้องเรียน (เช่น Mosquitto ภายในวง LAN หรือ Public Broker ที่กำหนด) ในรูปแบบ JSON
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** โค้ด MicroPython บน ESP32-S3 ที่ Publish ข้อมูล JSON เข้า Topic เฉพาะของทีมทุก 5 วินาที พร้อมหลักฐานการรับข้อมูลได้จริงบน MQTT Client (MQTT Explorer / Node-RED)
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. ติดตั้ง/คัดลอกไลบรารี `umqtt.simple` ลงบน ESP32-S3
    2. ตั้งชื่อ Client ID ไม่ซ้ำใคร (สำคัญมาก ไม่งั้น Broker จะเตะหลุด!) และตั้งชื่อ Topic ของทีม (เช่น `school/m5/team01/env`)
    3. อ่านค่าเซนเซอร์ แปลงเป็นข้อความ JSON ด้วย `ujson.dumps({"temp": t, "light": l})`
    4. สั่ง `client.publish(topic, payload)` แล้วเปิดดูผลบน MQTT Explorer บนคอมพิวเตอร์
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - เชื่อมต่อ MQTT Broker สำเร็จโดยไม่หลุดชนกับกลุ่มอื่น (3 คะแนน)
    - Publish ค่าเซนเซอร์จริงในรูปแบบ JSON เข้า Topic ที่กำหนด (5 คะแนน)
    - ตรวจสอบเห็นข้อมูลจริงบน MQTT Client (2 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** บนหน้าจอ MQTT Explorer เห็น Topic `school/m5/team01/env` มี JSON `{"temp": 29.0, "light": 450}` อัปเดตทุก 5 วิ
  - **ตัวเลือกเสริม (Extension):** ตั้งค่า `retain=True` ให้ข้อความล่าสุดค้างไว้บน Broker
  - **แนวทางช่วยเหลือ (Scaffold):** เตรียมไฟล์ `umqtt/simple.py` และตั้ง MQTT Broker กลางของห้อง (หรือใช้ Broker สาธารณะที่ปลอดภัย) ให้พร้อมเชื่อมต่อ
- **วัสดุ/เครื่องมือที่ต้องเตรียม:** ESP32-S3, เซนเซอร์, Wi-Fi, คอมพิวเตอร์ + MQTT Explorer `[เสริม]`, MQTT Broker (Mosquitto)
- **คำถามสะท้อนคิดปิดคาบ:**
  1. ทำไม Client ID ของอุปกรณ์แต่ละตัวที่ต่อเข้า MQTT Broker จึงห้ามซ้ำกัน?
  2. การจัดโครงสร้างชื่อ Topic แบบมีลำดับชั้น (เช่น `building1/floor2/room204/temp`) มีข้อดีอย่างไร?

### คาบที่ 4: MQTT ขั้นสูง — Subscribe และสื่อสารสองทาง
- **จุดประสงค์การเรียนรู้:**
  1. เขียนฟังก์ชัน Callback เพื่อรับข้อความ (Subscribe) จาก MQTT Topic บน ESP32-S3 ได้
  2. สร้างระบบสื่อสารสองทาง (Publish ค่าเซนเซอร์ และ Subscribe รับคำสั่งควบคุมอุปกรณ์) ผ่าน Broker ได้
- **แนวคิดหลัก:** ความสามารถในการ Subscribe ทำให้ ESP32-S3 รับคำสั่งจากภายนอก (เช่น กดปุ่มจากหน้าเว็บ หรือรับคำสั่งจาก AI) เพื่อเปิด-ปิดไฟหรือมอเตอร์ได้ทันทีโดยไม่ต้องรีเฟรช
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | ทบทวน Publish จากคาบ 3 และแนะนำฟังก์ชัน Callback ของ `umqtt` |
  | 5–15 นาที | บรรยาย/สาธิต | สาธิต `client.set_callback(sub_cb)`, `client.subscribe(topic)`, และ `client.check_msg()` |
  | 15–25 นาที | ฝึกปฏิบัติแบบมีผู้ช่วย | ส่งข้อความ `"ON"` / `"OFF"` จาก MQTT Explorer ไปสั่ง Onboard LED ของ ESP32-S3 |
  | **25–50 นาที (50%)** | **โครงงานปลายคาบ** | ลงมือทำเอง |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** ระบบสื่อสารสองทางข้ามอุปกรณ์ผ่าน MQTT (Two-Way MQTT Control)
  - **โจทย์/สถานการณ์:** สร้างระบบที่ ESP32-S3 ทำงาน 2 ทางพร้อมกัน: ส่งค่าเซนเซอร์/ปุ่มกดขึ้น Broker และรับคำสั่งจาก Broker มาเปิด-ปิด LED/Servo (หรือจับคู่กับบอร์ดเพื่อน: กดปุ่มบอร์ด A → ไฟบอร์ด B ติด!)
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** ระบบ ESP32-S3 ที่ทั้ง Publish สถานะตนเองและ Subscribe รับคำสั่ง `"ON"`/`"OFF"` มาควบคุม LED/Servo ได้จริงแบบไม่ค้าง (ใช้ `check_msg()` คู่กับจับเวลา `ticks_ms()`)
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. เขียนฟังก์ชัน `on_message(topic, msg)` ตรวจสอบ `if msg == b"ON": led.value(1)`
    2. ลงทะเบียน Callback และ `client.subscribe(b"school/m5/team01/cmd")`
    3. ในลูปหลัก เรียก `client.check_msg()` ถี่ ๆ (เช่น ทุก 0.1 วิ) และใช้ `time.ticks_ms()` เพื่อส่งค่าเซนเซอร์ทุก ๆ 5 วินาที (ไม่ใช้ `sleep(5)` ยาว ๆ ไม่งั้นรับคำสั่งช้า!)
    4. ทดสอบสั่งเปิด-ปิดไฟจาก MQTT Explorer (หรือจับคู่สั่งข้ามบอร์ดกับเพื่อน)
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - Subscribe และสั่งงานฮาร์ดแวร์ผ่าน Callback ได้ถูกต้อง (4 คะแนน)
    - Publish และ Subscribe ทำงานร่วมกันได้โดยไม่บล็อกลูป (`ticks_ms()`) (4 คะแนน)
    - ทดสอบสื่อสารสองทางสำเร็จจริง (2 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** กดส่ง `"ON"` ใน MQTT Explorer → LED บนบอร์ดติดในเสี้ยววินาที ขณะเดียวกันค่าเซนเซอร์ยังส่งขึ้นทุก 5 วินาที
  - **ตัวเลือกเสริม (Extension):** ทำภารกิจจับคู่บอร์ด: บอร์ดทีม A กดปุ่ม/บังแสง → Publish เข้า Topic ของทีม B → ไฟทีม B ติด
  - **แนวทางช่วยเหลือ (Scaffold):** เตือนเรื่อง `msg` ที่รับมาใน Callback เป็นชนิด `bytes` (`b"ON"`) ต้องแปลง `.decode()` หรือเทียบกับ `b"ON"`
- **วัสดุ/เครื่องมือที่ต้องเตรียม:** ESP32-S3, LED/Servo, ปุ่มกด/เซนเซอร์, MQTT Broker, MQTT Explorer
- **คำถามสะท้อนคิดปิดคาบ:**
  1. ทำไมเราจึงไม่ควรใช้ `time.sleep(10)` ในลูปที่มี `client.check_msg()`?
  2. ข้อความ `msg` ที่เข้ามาในฟังก์ชัน Callback ของ MicroPython เป็นข้อมูลชนิดใด?
