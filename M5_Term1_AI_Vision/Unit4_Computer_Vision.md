### คาบที่ 24: ภาพรวมงาน Computer Vision 3 ประเภท
- **จุดประสงค์การเรียนรู้:**
  1. จำแนกความแตกต่างระหว่าง Image Classification, Object Detection และ Image Segmentation ได้
  2. เลือกประเภทงาน Computer Vision และโครงสร้างข้อมูลผลลัพธ์ให้เหมาะกับโจทย์จริงได้
- **แนวคิดหลัก:** งาน Computer Vision ตอบคำถามต่างระดับกัน: Classification ("ภาพนี้คืออะไร?"), Detection ("อยู่ตรงไหนบ้าง กี่ชิ้น?"), และ Segmentation ("อยู่พิกเซลไหนบ้าง?")
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | แสดงภาพถนน 1 ภาพแล้วถาม 3 คำถามเพื่อชี้ความต่างของ 3 งาน CV |
  | 5–15 นาที | บรรยาย/สาธิต | อธิบาย Classification / Detection / Segmentation และตัวอย่างการใช้งานจริง |
  | 15–25 นาที | ฝึกปฏิบัติแบบมีผู้ช่วย | วิเคราะห์ระบบรถไร้คนขับและระบบแพทย์ว่าใช้ CV ประเภทไหน |
  | **25–50 นาที (50%)** | **โครงงานปลายคาบ** | ลงมือทำเอง |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** ตารางสถาปัตยกรรมระบบ CV ในโลกจริง
  - **โจทย์/สถานการณ์:** นักเรียนสวมบทที่ปรึกษา AI ต้องวิเคราะห์โจทย์ 6 สถานการณ์จริง (เช่น ตรวจจับหมวกกันน็อก, คัดแยกสายพันธุ์สุนัข, วัดพื้นที่ป่าไม้จากดาวเทียม, นับจำนวนรถยนต์, ตรวจรอยร้าวบนถนน, สแกนโรคใบไม้) เพื่อเลือกประเภทงาน CV ที่เหมาะสมที่สุด
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** เอกสาร/สไลด์วิเคราะห์ 6 ระบบ CV จริง ระบุ: ประเภทงาน (Classification/Detection/Segmentation), Input, Output ที่ได้, และเหตุผลที่ไม่เลือกอีก 2 แบบ
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. ศึกษา 6 โจทย์สถานการณ์ที่กำหนด (หรือเลือกจากอุตสาหกรรมที่สนใจ)
    2. พิจารณาว่าโจทย์ต้องการแค่ชื่อภาพ, ตำแหน่งกล่อง, หรือขอบเขตระดับพิกเซล
    3. กรอกลงตารางวิเคราะห์พร้อมระบุความยากในการเตรียมข้อมูล (Labeling) ของแต่ละแบบ
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - เลือกประเภทงาน CV ได้ถูกต้องครบทั้ง 6 ระบบ (5 คะแนน)
    - อธิบาย Input/Output และเหตุผลประกอบได้ชัดเจน (3 คะแนน)
    - เปรียบเทียบต้นทุนการเตรียมข้อมูลของแต่ละงานได้ถูกต้อง (2 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** "นับจำนวนคนไม่ใส่หมวกกันน็อกในกล้องวงจรปิด → Object Detection เพราะมีหลายคนใน 1 เฟรมและต้องตีกรอบระบุตำแหน่ง"
  - **ตัวเลือกเสริม (Extension):** เสนอไอเดียโครงงาน CV ของทีมตนเองสำหรับคาบ 25–30 โดยระบุประเภทงานและคลาสที่จะเก็บ
  - **แนวทางช่วยเหลือ (Scaffold):** แจกการ์ดสรุป 3 งาน CV พร้อมภาพตัวอย่าง Output ของแต่ละแบบ
- **วัสดุ/เครื่องมือที่ต้องเตรียม:** คอมพิวเตอร์, Google Docs/Slides
- **คำถามสะท้อนคิดปิดคาบ:**
  1. ทำไมการเตรียม Dataset สำหรับ Segmentation จึงใช้เวลาและแรงงานมากกว่า Classification มาก?
  2. ถ้าในภาพมีวัตถุหลายชนิดปนกัน (เช่น หมาและแมวอยู่ในภาพเดียวกัน) Classification จะเจอปัญหาอะไร?

### คาบที่ 25: ออกแบบ Dataset ภาพและการถ่ายเก็บข้อมูล
- **จุดประสงค์การเรียนรู้:**
  1. วางแผนการเก็บข้อมูลภาพสำหรับโจทย์จำแนกภาพของทีมให้ครอบคลุมความหลากหลาย (แสง มุม ระยะ ฉากหลัง) ได้
  2. ถ่ายภาพเก็บ Dataset รอบแรกอย่างมีคุณภาพเพื่อป้องกันอคติจากฉากหลัง (Background Bias) ได้
- **แนวคิดหลัก:** ถ้าถ่ายรูปคลาส A บนโต๊ะขาว และถ่ายคลาส B บนโต๊ะดำ โมเดลจะแอบจำสีโต๊ะแทนตัววัตถุ! จึงต้องวางแผนถ่ายให้ฉากหลังและมุมกล้องหลากหลาย
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | เล่าเคสคลาสสิก: โมเดลแยกสุนัขป่ากับหมาบ้านโดยดูจาก "หิมะ" ในฉากหลัง |
  | 5–15 นาที | บรรยาย/สาธิต | สอนหลักเก็บ Dataset คุณภาพ (3–4 คลาส, มุมหลากหลาย, แสงต่างกัน, ไม่เบลอ) |
  | 15–20 นาที | จัดทีมวางแผน | แบ่งทีม (2–3 คน) กำหนดโจทย์และคลาสของทีม |
  | **20–50 นาที (60%)** | **โครงงานปลายคาบ** | ลงมือทำเอง (ถ่ายเก็บภาพจริง) |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** ชุดข้อมูลภาพของทีม (ระยะที่ 1: เก็บภาพ ≥ 50 ภาพ/คลาส)
  - **โจทย์/สถานการณ์:** ทีมต้องสร้างชุดข้อมูลภาพของตนเอง (3–4 คลาส เช่น ประเภทขยะ, ท่าทางมือ, อุปกรณ์การเรียน, ป้ายสัญญาณ, หรือใบไม้) เพื่อนำไปฝึกโมเดลในคาบ 27–30
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** แผนการเก็บข้อมูลสั้น + โฟลเดอร์ภาพรอบแรกที่เก็บได้จริงอย่างน้อย **50 ภาพต่อคลาส** (เปลี่ยนมุม/ระยะ/ฉากหลังอย่างน้อย 3 แบบ)
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. ตั้งชื่อคลาส 3–4 คลาส (ใช้ภาษาอังกฤษไม่มีเว้นวรรค เช่น `plastic_bottle`, `can`, `paper`)
    2. แบ่งหน้าที่ในทีมช่วยกันถ่ายภาพด้วยมือถือ/เว็บแคมโดยขยับมุม ระยะ และเปลี่ยนฉากหลัง
    3. อัปโหลดลง Google Drive แยกโฟลเดอร์ตามชื่อคลาส
    4. ตรวจนับจำนวนเบื้องต้นให้ได้ ≥ 50 ภาพ/คลาส (และเก็บเพิ่มอีก 50 ภาพในคาบ 26)
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - กำหนดโจทย์และคลาสชัดเจน เหมาะสมกับบริบทจริง (2 คะแนน)
    - เก็บภาพได้ ≥ 50 ภาพต่อคลาส (4 คะแนน)
    - ภาพมีความหลากหลายของมุมกล้อง แสง และฉากหลัง (4 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** ทีม "แยกขยะ 3 คลาส" เก็บภาพขวดพลาสติก กระป๋อง กล่องกระดาษ ได้คลาสละ 55 ภาพ ทั้งบนโต๊ะ พื้น และถือในมือ
  - **ตัวเลือกเสริม (Extension):** เก็บภาพจากแหล่งอื่นที่ถูกลิขสิทธิ์ (เช่น ภาพถ่ายจากเพื่อนต่างมุม) มาผสมเพื่อให้หลากหลายขึ้น
  - **แนวทางช่วยเหลือ (Scaffold):** แจกเช็กลิสต์การถ่ายภาพ 4 มุม (ตรง, เอียง 45°, ใกล้, ไกล) x 3 ฉากหลัง
- **วัสดุ/เครื่องมือที่ต้องเตรียม:** มือถือ/เว็บแคม, คอมพิวเตอร์, Google Drive
- **คำถามสะท้อนคิดปิดคาบ:**
  1. ทำไมเราถึงไม่ควรวางวัตถุไว้ที่เดิมแล้วกดถ่ายรัว ๆ 50 ช็อตติดกัน?
  2. คลาสไหนของทีมคุณที่ถ่ายยากที่สุดหรือมีลักษณะคล้ายกับอีกคลาสมากที่สุด?

### คาบที่ 26: จัดการ Dataset — ติดป้าย ตรวจสอบ และแบ่ง Train/Val/Test
- **จุดประสงค์การเรียนรู้:**
  1. เก็บภาพเพิ่มเติมจนครบ ≥ 100 ภาพต่อคลาส และตรวจสอบความสะอาด/ความสมดุลของ Dataset ได้
  2. เขียนสคริปต์ Python จัดการโฟลเดอร์ แบ่งชุด Train / Val / Test (เช่น 70/15/15) โดยไม่เกิดข้อมูลซ้ำข้ามชุดได้
- **แนวคิดหลัก:** Dataset ที่ดีต้องสมดุล (Class Balance) ไม่มีภาพเสียหรือติดป้ายผิด และต้องแยก Test Set ออกมาเก็บไว้ต่างหากก่อนเริ่มฝึกโมเดลเสมอ
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | ตรวจสอบความคืบหน้าภาพจากคาบ 25 |
  | 5–15 นาที | บรรยาย/สาธิต | สาธิตสคริปต์ Python ตรวจไฟล์ภาพเสีย นับจำนวนต่อคลาส และแบ่งโฟลเดอร์ `train/val/test` |
  | **15–50 นาที (70%)** | **โครงงานปลายคาบ** | ลงมือทำเอง (เก็บภาพให้ครบ ≥100 + จัดโครงสร้างโฟลเดอร์) |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** ชุดข้อมูลภาพมาตรฐานของทีม (Team Dataset ≥ 100 Images/Class)
  - **โจทย์/สถานการณ์:** ต่อยอดจากคาบ 25 ให้ครบอย่างน้อย 100 ภาพต่อคลาส ตรวจสอบคุณภาพทุกภาพ และแบ่งสัดส่วน Train / Val / Test บน Google Drive พร้อมฝึกในคาบหน้า
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** โฟลเดอร์ Dataset ของทีมบน Google Drive ที่มีภาพ ≥ 100 ภาพต่อคลาส แบ่งเป็นโฟลเดอร์ `train/`, `val/`, `test/` เรียบร้อย + กราฟแท่งแสดงจำนวนภาพแต่ละคลาสใน Colab
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. ถ่ายภาพเพิ่มให้ครบ ≥ 100 ภาพต่อคลาส (ควรมีภาพที่ถ่ายในสภาพแสง/มุมใหม่สำหรับ Test Set โดยเฉพาะ)
    2. ลบภาพที่เบลอ มืดสนิท หรือผิดคลาสออก
    3. รันสคริปต์ Python ใน Colab เพื่อตรวจสอบไฟล์ภาพที่เปิดได้ทั้งหมดและแบ่งคัดลอกเข้าโฟลเดอร์ `train` (70%), `val` (15%), `test` (15%)
    4. วาดกราฟแท่งยืนยันความสมดุลของจำนวนภาพทุกคลาส
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - มีภาพสะอาดครบ ≥ 100 ภาพต่อคลาส และสมดุลกัน (4 คะแนน)
    - แบ่งโฟลเดอร์ `train/val/test` ถูกต้อง ไม่มีไฟล์เสีย (4 คะแนน)
    - แสดงกราฟ/สรุปสถิติ Dataset ได้ถูกต้อง (2 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** 3 คลาส คลาสละ 105 ภาพ แบ่งเป็น Train 73, Val 16, Test 16 ครบทุกคลาส และไม่มีภาพซ้ำข้ามชุด
  - **ตัวเลือกเสริม (Extension):** แปลงชื่อไฟล์ทั้งหมดให้เป็นมาตรฐานเดียวกัน (เช่น `plastic_001.jpg`) ด้วย Python
  - **แนวทางช่วยเหลือ (Scaffold):** เตรียมสคริปต์ Python (`split_dataset.py`) บน Colab ให้ทีมระบุเพียง Path ต้นทางและปลายทาง
- **วัสดุ/เครื่องมือที่ต้องเตรียม:** มือถือ/เว็บแคม, คอมพิวเตอร์, Google Colab, Google Drive
- **คำถามสะท้อนคิดปิดคาบ:**
  1. ถ้าเราถ่ายภาพต่อเนื่องเป็นวิดีโอแล้วแตกเฟรมมาแบ่งสุ่มเข้า Train กับ Test จะเกิดปัญหาอะไร? (Data Leakage!)
  2. ทำไมเราจึงแยก Test Set ออกมาตั้งแต่ขั้นตอนนี้ก่อนจะเห็นผลโมเดล?

### คาบที่ 27: ฝึกโมเดลจำแนกภาพของทีมรอบแรกด้วย Transfer Learning
- **จุดประสงค์การเรียนรู้:**
  1. เชื่อมต่อ Google Drive เข้า Colab และโหลดชุดข้อมูล `train/`, `val/`, `test/` ของทีมเข้าสู่ TensorFlow Dataset ได้
  2. ฝึกโมเดล Transfer Learning (MobileNetV2) รอบแรก (Baseline) กับ Dataset ของทีมและบันทึกผลลัพธ์ได้
- **แนวคิดหลัก:** โมเดล Baseline รอบแรกช่วยให้รู้ขีดความสามารถตั้งต้นของ Dataset ก่อนจะนำไปปรับจูนหรือเก็บข้อมูลเพิ่ม
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | ทบทวน Transfer Learning จากคาบ 15–16 |
  | 5–15 นาที | บรรยาย/สาธิต | สาธิต `drive.mount` และโหลดข้อมูลจาก 3 โฟลเดอร์ `train/val/test` |
  | 15–22 นาที | ฝึกปฏิบัติแบบมีผู้ช่วย | Mount Drive และเช็กให้แน่ใจว่า Colab อ่านโฟลเดอร์ภาพของทีมได้เร็ว (แนะนำคัดลอกลง `/content/` ชั่วคราว) |
  | **22–50 นาที (56%)** | **โครงงานปลายคาบ** | ลงมือทำเอง |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** โมเดลจำแนกภาพของทีม รุ่นที่ 1 (Team Baseline Model v1)
  - **โจทย์/สถานการณ์:** ฝึกโมเดล AI ของทีมเป็นครั้งแรกด้วยชุดข้อมูลจริง ≥ 100 ภาพ/คลาส เพื่อดูความแม่นยำตั้งต้น
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** Colab Notebook ฝึกโมเดล MobileNetV2 รอบแรกบน Dataset ของทีม พร้อมกราฟ Loss/Acc และค่า Validation/Test Accuracy ตั้งต้น
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. Mount Google Drive และคัดลอกโฟลเดอร์ Dataset มาไว้ใน `/content/dataset` (เพื่อให้อ่านไฟล์เร็วขึ้นมาก)

  - **ชื่อโครงงาน:** เครื่องวิเคราะห์วิดีโอจราจร/คนเดินอัตโนมัติ (Video Analytics)

  - **ชิ้นงานที่ต้องส่ง (Deliverable):** ไฟล์วิดีโอผลลัพธ์ `.mp4` ที่ดาวน์โหลดมาเปิดดูได้ มีกรอบ Detection และข้อความนับจำนวนวัตถุแบบเรียลไทม์บนมุมจอ
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. อัปโหลดคลิปสั้น 5–10 วินาที (หรือใช้คลิปตัวอย่างที่ครูเตรียมให้)
    2. เปิดคลิปด้วย `cv2.VideoCapture` และสร้าง `VideoWriter` ด้วยขนาดเฟรมเดียวกัน
    3. วนลูปทีละเฟรม → รัน `model(frame, verbose=False)` → วาดผลลัพธ์ `annotated = results[0].plot()`

  - **แนวทางช่วยเหลือ (Scaffold):** เตรียมคลิปวิดีโอสั้น 5 วินาที (ขนาดไม่ใหญ่เกินไป) และโค้ด `VideoWriter` ที่ตั้งค่า Codec `mp4v` ให้เรียบร้อย

### คาบที่ 35: ความเป็นส่วนตัวของภาพ อคติของ Dataset และทดสอบย่อย CV
- **จุดประสงค์การเรียนรู้:**
  1. วิเคราะห์ความเสี่ยงด้านความเป็นส่วนตัวของภาพ (เช่น ใบหน้า ป้ายทะเบียน) และอคติใน Dataset ภาพได้
  2. เสนอแนวทางป้องกันทางเทคนิค (เช่น เบลอใบหน้าด้วย OpenCV) และผ่านแบบทดสอบย่อย Computer Vision ได้
- **แนวคิดหลัก:** ระบบ AI Vision ที่เก็บภาพจากที่สาธารณะอาจละเมิดความเป็นส่วนตัว หรือมีอคติหากข้อมูลฝึกไม่ครอบคลุมทุกกลุ่มประชากรและสภาพแวดล้อม
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | ยกตัวอย่างกรณีศึกษาอคติของระบบจดจำใบหน้า (Facial Recognition Bias) |
  | 5–12 นาที | บรรยาย/สาธิต | อธิบาย Visual Privacy, Dataset Bias และสาธิตการเบลอพื้นที่ใบหน้า/ป้ายทะเบียนด้วย OpenCV |
  | 12–22 นาที | ทดสอบย่อย | ทำแบบทดสอบย่อยหน่วย Computer Vision (10 นาที) |
  | **22–50 นาที (56%)** | **โครงงานปลายคาบ** | ลงมือทำเอง |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** ระบบปกป้องความเป็นส่วนตัวอัตโนมัติ (Auto Privacy Blur) + การ์ดตรวจอคติ
  - **โจทย์/สถานการณ์:** ก่อนเผยแพร่ภาพถ่ายในที่สาธารณะหรือนำไปฝึก AI ต้องมีระบบเบลอใบหน้าบุคคลอัตโนมัติและตรวจสอบอคติของ Dataset
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** (1) สคริปต์ OpenCV (ใช้ Haar Cascade หรือ YOLO ตรวจจับบุคคล/ใบหน้า แล้วใช้ `cv2.GaussianBlur` เบลอทับพื้นที่นั้น) ที่ทำงานได้จริงกับภาพ 1 ภาพ, (2) การ์ดตรวจสอบอคติ Dataset ของทีม 3 ข้อ
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. โหลด `cv2.CascadeClassifier(cv2.data.haarcascades + 'haarcascade_frontalface_default.xml')`
    2. ตรวจจับพิกัดใบหน้า `(x, y, w, h)` ในภาพตัวอย่าง
    3. ดึงเฉพาะส่วน `roi = img[y:y+h, x:x+w]`, ทำ `GaussianBlur` แล้ววางทับกลับลงบนภาพเดิม
    4. เขียนการ์ดตรวจอคติ Dataset ของทีม (เช่น แสง, สีผิว/วัสดุ, ฉากหลัง)
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - สคริปต์ตรวจจับและเบลอพื้นที่ใบหน้าทำงานได้จริง (4 คะแนน)
    - วิเคราะห์ความเสี่ยงความเป็นส่วนตัวและอคติของ Dataset ทีมได้ชัดเจน (3 คะแนน)
    - ผ่านเกณฑ์แบบทดสอบย่อย Computer Vision (3 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** ภาพหมู่เพื่อนที่ใบหน้าทุกคนถูกเบลออัตโนมัติ และการ์ดระบุว่า "Dataset ทีมควรถ่ายในห้องแสงน้อยเพิ่มเพื่อลดอคติแสงจ้า"
  - **ตัวเลือกเสริม (Extension):** เบลอเฉพาะบุคคลที่ไม่ต้องการเปิดเผย หรือเปลี่ยนเป็นแถบคาดตา (Pixelate Effect)
  - **แนวทางช่วยเหลือ (Scaffold):** เตรียมโค้ดโหลด Haar Cascade 3 บรรทัดให้พร้อมใช้งาน
