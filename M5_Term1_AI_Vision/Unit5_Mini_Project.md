### คาบที่ 36: เสนอโจทย์ Mini Project และวางแผนข้อมูล
- **จุดประสงค์การเรียนรู้:**
  1. กำหนดโจทย์ระบบ AI จำแนกภาพหรือตรวจจับวัตถุที่แก้ปัญหาจริงและมีผู้ใช้เป้าหมายชัดเจนได้
  2. วางแผนการเก็บ Dataset (จำนวนคลาส จำนวนภาพ สภาพแวดล้อม) และเกณฑ์วัดความสำเร็จได้
- **แนวคิดหลัก:** Mini Project ปลายภาคต้องไม่ใช่แค่รันโค้ดเดิมซ้ำ แต่ต้องกำหนดโจทย์ใหม่หรือยกระดับระบบให้แก้ปัญหาได้จริงและวัดผลได้ชัดเจน
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | ชี้แจงกรอบเวลา 5 คาบ (วางแผน → เก็บข้อมูล → ฝึก/ปรับปรุง → เดโม) และตัวอย่างโจทย์ |
  | 5–15 นาที | บรรยาย/สาธิต | แนะนำโครงสร้าง Proposal และวิธีกำหนดเกณฑ์สำเร็จ (เช่น Test Acc ≥ 88%, ใช้งานผ่าน Gradio ได้) |
  | 15–22 นาที | ระดมสมองทีม | แบ่งกลุ่ม 2–3 คน เลือกโจทย์จริงในโรงเรียน/ชีวิตประจำวัน |
  | **22–50 นาที (56%)** | **โครงงานปลายคาบ** | ลงมือทำเอง |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** ใบเสนอโจทย์และแผนเก็บข้อมูล Mini Project (AI Vision Proposal)
  - **โจทย์/สถานการณ์:** ทีมต้องเสนอโครงการสร้างระบบ AI จำแนกภาพ/ตรวจจับวัตถุที่ใช้งานได้จริง (เช่น แยกขยะ 4 ประเภท, ตรวจโรคใบไม้, อ่านภาษามือเบื้องต้น, ตรวจการแต่งกาย/อุปกรณ์นิรภัย)
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** ใบเสนอโจทย์ 1 หน้า ประกอบด้วย: ปัญหาและผู้ใช้เป้าหมาย, รายชื่อคลาส (≥ 3 คลาส), แผนเก็บภาพ (จำนวน/สถานที่/แสง), เทคโนโลยีที่ใช้ (MobileNet/YOLO + OpenCV + Gradio), และเกณฑ์สำเร็จ
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. เลือกโจทย์และกำหนดคลาส (3–5 คลาส)
    2. ออกแบบเกณฑ์การถ่ายภาพเพื่อป้องกันอคติ
    3. ระบุ Pipeline ตั้งแต่รับภาพ → โมเดล → หน้าจอผลลัพธ์ (Gradio/เว็บแคม)
    4. นำเสนอ 1 นาทีสั้น ๆ กับครูเพื่อรับอนุมัติก่อนเก็บภาพในคาบ 37
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - โจทย์แก้ปัญหาจริงและมีผู้ใช้ชัดเจน (3 คะแนน)
    - แผนเก็บข้อมูลครอบคลุมและป้องกันอคติได้ (4 คะแนน)
    - ขอบเขตและเกณฑ์สำเร็จเหมาะสมกับเวลาที่เหลือ (3 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** "ระบบคัดแยกขยะในโรงอาหาร 4 คลาส (พลาสติก, กระป๋อง, กระดาษ, เศษอาหาร)" พร้อมแผนเก็บคลาสละ 100 ภาพในสภาพแสงโรงอาหารจริง
  - **ตัวเลือกเสริม (Extension):** ออกแบบ Mockup หน้าจอ Gradio และข้อความคำแนะนำที่จะแสดงเมื่อทายผลแต่ละคลาส
  - **แนวทางช่วยเหลือ (Scaffold):** เตรียมรายการโจทย์แนะนำ 5 แนวทางและแบบฟอร์ม Proposal 1 หน้า
- **วัสดุ/เครื่องมือที่ต้องเตรียม:** คอมพิวเตอร์, LibreOffice Writer / Markdown [เสริม]/Slides, ใบเสนอโจทย์
- **คำถามสะท้อนคิดปิดคาบ:**
  1. มีจุดเสี่ยงอะไรในการเก็บภาพจริงของโจทย์ทีมคุณ (เช่น แสงน้อย, วัตถุคล้ายกัน) และจะเตรียมรับมืออย่างไรในคาบ 37?
- **การบ้าน/การเตรียมตัวสำหรับคาบถัดไป:** เตรียมวัตถุตัวอย่างจริงหรือสถานที่ที่จะไปถ่ายเก็บภาพในคาบ 37

### คาบที่ 37: เก็บและเตรียม Dataset สำหรับ Mini Project
- **จุดประสงค์การเรียนรู้:**
  1. เก็บภาพจริงของโจทย์ Mini Project ให้ครบถ้วน สมดุล และหลากหลายตามแผนที่วางไว้ได้
  2. ตรวจสอบคุณภาพ ติดป้ายกำกับ และแบ่งชุดข้อมูล Train / Val / Test บน NAS Storage (Synology DS223j) อย่างถูกต้องได้
- **แนวคิดหลัก:** คาบนี้ทุ่มเวลาทั้งหมดให้กับการสร้าง Dataset คุณภาพสูงของโครงงานปลายภาค เพราะข้อมูลที่ดีคือครึ่งหนึ่งของความสำเร็จ
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | ทบทวนกฎ Data Hygiene และแบ่งหน้าที่ในทีม (คนจัดวัตถุ / คนถ่าย / คนคัดกรอง) |
  | **5–50 นาที (90%)** | **โครงงานปลายคาบ** | ลงมือทำเอง (เก็บภาพจริง + คัดกรอง + Split โฟลเดอร์) |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** ชุดข้อมูล Mini Project ฉบับพร้อมฝึก (Verified Team Dataset)
  - **โจทย์/สถานการณ์:** ลงพื้นที่ถ่ายภาพจริง (หรือใช้วัตถุตัวอย่างในห้อง) เพื่อสร้าง Dataset ประจำโครงงานให้สะอาดและพร้อมป้อนเข้า JupyterHub
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** โฟลเดอร์ Dataset ของ Mini Project บน NAS Storage (Synology DS223j) (≥ 80–100 ภาพ/คลาส, แบ่ง `train/val/test` เรียบร้อย) + ภาพแคปกราฟนับจำนวนภาพแต่ละคลาสใน JupyterHub
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. ถ่ายเก็บภาพจริงตามแผน (เปลี่ยนมุม แสง ระยะ)
    2. คัดภาพเบลอ/ผิดคลาสทิ้ง
    3. อัปโหลดขึ้น Drive และรันสคริปต์แบ่ง `train/val/test`
    4. ตรวจสอบจำนวนภาพทุกคลาสและแจ้งครูตรวจความพร้อมท้ายคาบ
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - เก็บภาพจริงครบตามเป้าหมายและสมดุลทุกคลาส (4 คะแนน)
    - ภาพคมชัด หลากหลาย ไม่ติดอคติฉากหลัง (3 คะแนน)
    - แบ่ง `train/val/test` ถูกต้องพร้อมฝึกทันทีในคาบ 38 (3 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** 4 คลาส คลาสละ 90 ภาพ สะอาด ไม่มีภาพเสีย แบ่งโฟลเดอร์ `train/val/test` เสร็จเรียบร้อย
  - **ตัวเลือกเสริม (Extension):** เก็บ "ชุดภาพทดสอบสุดโหด (Hard Test Cases)" เพิ่มอีก 10 ภาพที่ถ่ายในมุมแปลกหรือแสงน้อย
  - **แนวทางช่วยเหลือ (Scaffold):** ใช้สคริปต์ `split_dataset.py` จากคาบ 26 เพื่อความรวดเร็ว
- **วัสดุ/เครื่องมือที่ต้องเตรียม:** มือถือ/กล้อง, วัตถุจริงสำหรับถ่ายภาพ, คอมพิวเตอร์, NAS Storage (Synology DS223j)/JupyterHub
- **คำถามสะท้อนคิดปิดคาบ:**
  1. ภาพที่เก็บได้วันนี้มีความสมดุลและความหลากหลายเพียงพอหรือยัง?
  2. คาดว่าโมเดลจะสับสนคลาสไหนกับคลาสไหนมากที่สุดตอนเริ่มฝึกในคาบหน้า?

### คาบที่ 38: ฝึกและประเมินผลโมเดล Mini Project รอบแรก (Checkpoint 1)
- **จุดประสงค์การเรียนรู้:**
  1. ฝึกโมเดล AI Vision ของ Mini Project รอบแรกและประเมินผลด้วย Accuracy, Confusion Matrix และ Precision/Recall ได้
  2. วิเคราะห์ Error Analysis เพื่อกำหนดแผนปรับปรุงโมเดลและข้อมูลในคาบถัดไปได้
- **แนวคิดหลัก:** Checkpoint 1 เน้นให้ได้โมเดลที่รันได้จริงและเห็นผลลัพธ์เชิงตัวเลข พร้อมระบุจุดบกพร่องที่ต้องแก้ไข
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | แจ้งเป้าหมาย Checkpoint 1: ต้องได้โมเดลรันผ่าน + Confusion Matrix + แผนแก้จุดอ่อน |
  | **5–50 นาที (90%)** | **โครงงานปลายคาบ** | ลงมือทำเอง (ครูเดินตรวจ Checkpoint 1) |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** Mini Project Checkpoint 1 — โมเดลและรายงานผลรอบแรก
  - **โจทย์/สถานการณ์:** ฝึกโมเดลจาก Dataset คาบ 37 บน JupyterHub บน AI Server GPU และตรวจวัดจุดอ่อนจากภาพที่ทายผิด
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** Jupyter Notebook (บน JupyterHub) ที่ฝึกโมเดลรอบแรกสำเร็จ, แสดง Learning Curve, Confusion Matrix, `classification_report`, และลิสต์จุดอ่อนที่ต้องแก้ในคาบ 39 (ผ่าน Checkpoint 1)
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. คัดลอก Dataset ลง `/content/` และโหลด `train/val/test`
    2. ฝึกโมเดล (Transfer Learning + Augmentation + EarlyStopping)
    3. รันประเมินผลบน `test_ds` และสร้าง Confusion Matrix
    4. ดูภาพที่ทายผิดและจดบันทึกลงในโน้ตบุ๊กว่าจะปรับแก้อะไร (เช่น เก็บภาพเพิ่ม, ปรับ Crop/Augmentation, หรือ Fine-tune)
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - โมเดลฝึกบนข้อมูล Mini Project สำเร็จ (4 คะแนน)
    - ประเมินผลด้วย Confusion Matrix และ Precision/Recall ครบถ้วน (3 คะแนน)
    - วิเคราะห์จุดผิดพลาดและวางแผนแก้ไขได้ชัดเจน (3 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** ได้ Test Acc 84% และชี้จุดผิดจาก Confusion Matrix ได้ชัด 2 จุดพร้อมแผนแก้ไข
  - **ตัวเลือกเสริม (Extension):** ทดลองใช้ OpenCV ช่วย Crop หรือปรับแสงภาพก่อนส่งเข้าโมเดล
  - **แนวทางช่วยเหลือ (Scaffold):** ครูช่วยดู Learning Curve ของแต่ละกลุ่มว่ามีอาการ Underfit หรือ Overfit
- **วัสดุ/เครื่องมือที่ต้องเตรียม:** คอมพิวเตอร์, JupyterHub (RTX 3090 บน AI Server), Dataset จากคาบ 37
- **คำถามสะท้อนคิดปิดคาบ:**
  1. ผลลัพธ์รอบแรกเป็นไปตามเกณฑ์สำเร็จที่ตั้งไว้ในคาบ 36 หรือยัง?
  2. คาบหน้าต้องปรับข้อมูลหรือปรับโมเดลตรงไหนเป็นอันดับแรก?

### คาบที่ 39: ปรับปรุงโมเดลและสร้างระบบสาธิตฉบับสมบูรณ์ (Checkpoint 2)
- **จุดประสงค์การเรียนรู้:**
  1. ปรับปรุงโมเดลและ/หรือข้อมูลตามแผนจาก Checkpoint 1 จนได้ความแม่นยำตามเกณฑ์ได้
  2. ห่อโมเดลเป็นระบบที่ใช้งานได้จริง (Gradio Web App หรือ Live Camera) พร้อมเตรียมสไลด์นำเสนอสำหรับ Demo Day ได้
- **แนวคิดหลัก:** ระบบ AI ที่สมบูรณ์ต้องทั้งแม่นยำ (จาก Data-Centric Tuning) และเข้าถึงได้ง่าย (ผ่าน UI ที่ผู้ใช้ทดสอบได้จริง)
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | แจ้งเป้าหมาย Checkpoint 2: โมเดลฉบับสมบูรณ์ + UI ใช้งานจริง + ซ้อมเดโม |
  | **5–50 นาที (90%)** | **โครงงานปลายคาบ** | ลงมือทำเอง (ครูตรวจ Checkpoint 2) |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** Mini Project Checkpoint 2 — ระบบ AI Vision พร้อมใช้งานจริง
  - **โจทย์/สถานการณ์:** อัปเกรดโมเดลจากคาบ 38 และสร้างหน้าจอ Gradio (หรือระบบเว็บแคม) ให้คนทั่วไปใช้งานได้จริง พร้อมซ้อมสาธิต 3 นาที
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** (1) ไฟล์โมเดลฉบับสุดท้าย `.pth` + โค้ด Gradio Web App ที่รันได้จริง, (2) รายงานเปรียบเทียบผลก่อน-หลังปรับปรุง, (3) สไลด์สั้น 2–3 หน้า + คลิปสำรองตอนทดสอบผ่าน
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. ปรับปรุง Dataset/Fine-tune โมเดลตามแผนจากคาบ 38 และวัดผลเทียบกัน
    2. บันทึกโมเดลสุดท้ายแล้วสร้างหน้าจอ Gradio (แสดงผลทำนาย + ความมั่นใจ + คำแนะนำการใช้งาน)
    3. ทดสอบใช้งานจริงกับวัตถุหรือภาพใหม่ และอัดวิดีโอหน้าจอสำรอง 30 วิ
    4. เตรียมสไลด์สั้นและซ้อมนำเสนอ 3 นาที
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - โมเดลฉบับปรับปรุงมีความแม่นยำดีขึ้นหรือผ่านเกณฑ์สำเร็จ (4 คะแนน)
    - หน้าจอ UI (Gradio/Webcam) ใช้งานได้จริงและสื่อสารผลชัดเจน (4 คะแนน)
    - เตรียมสไลด์และคลิปสำรองพร้อมสำหรับ Demo Day (2 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** Test Acc เพิ่มจาก 84% → 92%, หน้าเว็บ Gradio แสดงผลแยกขยะพร้อมคำแนะนำถังที่ต้องทิ้งได้ทันที
