### คาบที่ 37: เลือกโจทย์ วางผังการทำงาน (Flowchart) และกำหนดเกณฑ์สำเร็จ
- **จุดประสงค์การเรียนรู้:**
  1. กำหนดโจทย์โครงงาน Python ที่มีขอบเขตเหมาะสมกับเวลา 3 คาบและใช้งานได้จริงได้
  2. เขียนผังการทำงาน (Flowchart) และกำหนดเกณฑ์ความสำเร็จ (Success Criteria) ของโปรแกรมได้
- **แนวคิดหลัก:** การวางแผนด้วย Flowchart และกำหนดเกณฑ์สำเร็จก่อนเขียนโค้ด ช่วยให้รู้ว่าต้องสร้างฟังก์ชันอะไรบ้างและป้องกันปัญหาขอบเขตงานบานปลาย
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | แนะนำแนวทาง Mini Project ปลายภาค (โปรแกรม Python 1 ชิ้นที่ใช้งานได้จริง) |
  | 5–15 นาที | บรรยาย/สาธิต | สอนสัญลักษณ์ Flowchart พื้นฐานและการเขียน Project Proposal สั้น |
  | 15–25 นาที | ฝึกปฏิบัติแบบมีผู้ช่วย | ปรึกษาไอเดียและคัดเลือกโจทย์ที่ทำได้จริงในเวลา 2 คาบถัดไป |
  | **25–50 นาที (50%)** | **โครงงานปลายคาบ** | ลงมือทำเอง |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** พิมพ์เขียว Mini Project (Project Blueprint & Flowchart)
  - **โจทย์/สถานการณ์:** นักเรียนต้องออกแบบโปรแกรม Python 1 ชิ้นที่แก้ปัญหาจริง (เช่น ระบบวิเคราะห์ข้อมูล CSV ของห้อง/ข้อมูลที่สนใจ หรือโปรแกรมจัดการการเงิน/การเรียน/ร้านค้าขนาดเล็ก)
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** ใบวางแผนโครงงาน 1 หน้า ประกอบด้วย: ชื่อโครงงาน, ปัญหาที่แก้, ข้อมูลนำเข้า-ผลลัพธ์, **Flowchart การทำงาน**, และเกณฑ์สำเร็จ 3 ข้อ (ต้องผ่านการอนุมัติจากครู)
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. เลือกโจทย์ที่สนใจ (เดี่ยวหรือคู่ตามความเหมาะสมของห้อง)
    2. ระบุ Input, Process, Output และโครงสร้าง Python ที่จะใช้ (ต้องมีอย่างน้อย ฟังก์ชัน + เงื่อนไข/ลูป หรือ pandas)
    3. วาด Flowchart ด้วย Draw.io (Offline) [เสริม] / โปรแกรมออกแบบออฟไลน์ (LibreOffice Impress / Draw.io) [เสริม] / Draw.io
    4. กำหนดเกณฑ์สำเร็จ 3 ข้อแล้วนำไปให้ครูตรวจอนุมัติท้ายคาบ
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - โจทย์ชัดเจน แก้ปัญหาได้จริง และขอบเขตพอดีเวลา (3 คะแนน)
    - Flowchart ถูกต้องตามลำดับตรรกะและอ่านเข้าใจง่าย (4 คะแนน)
    - เกณฑ์สำเร็จวัดผลได้จริง (3 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** ใบวางแผน "โปรแกรมวิเคราะห์พฤติกรรมการนอนและเกรดจาก CSV" พร้อม Flowchart ตั้งแต่โหลดไฟล์ → กรองข้อมูล → คำนวณค่าเฉลี่ย → วาดกราฟ 2 รูป
  - **ตัวเลือกเสริม (Extension):** ออกแบบหน้าตาเมนูข้อความ (UI Mockup) ของโปรแกรมล่วงหน้า
  - **แนวทางช่วยเหลือ (Scaffold):** เตรียมรายการโจทย์แนะนำ 5 แนวทางสำหรับผู้เรียนที่ยังคิดไม่ออก
- **วัสดุ/เครื่องมือที่ต้องเตรียม:** คอมพิวเตอร์, LibreOffice Writer / Markdown [เสริม]/Drawings/โปรแกรมออกแบบออฟไลน์ (LibreOffice Impress / Draw.io) [เสริม], ใบวางแผนโครงงาน
- **คำถามสะท้อนคิดปิดคาบ:**
  1. ฟีเจอร์ไหนในโครงงานของคุณที่สำคัญที่สุด (Must-have) และฟีเจอร์ไหนตัดออกได้ถ้าเวลาไม่พอ?
  2. Flowchart ช่วยให้เห็นจุดที่อาจเกิดข้อผิดพลาดตรงไหนบ้าง?

### คาบที่ 38: พัฒนา Mini Project (ส่วนรับข้อมูลและแกนประมวลผล)
- **จุดประสงค์การเรียนรู้:**
  1. เขียนโค้ดส่วนรับข้อมูล (Input / อ่านไฟล์ CSV) และโครงสร้างข้อมูลหลักตาม Flowchart ได้
  2. ทดสอบการทำงานของโมดูลแรกและผ่านจุดตรวจความคืบหน้ากับครูได้
- **แนวคิดหลัก:** การพัฒนาแบบแบ่งส่วน (Incremental Development) โดยสร้างแกนรับข้อมูลและทดสอบให้รันผ่านก่อน ช่วยลดความซับซ้อนในการดีบัก
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | ทบทวน Flowchart ของแต่ละคนและแจ้งเกณฑ์จุดตรวจ (Checkpoint 1) |
  | 5–10 นาที | แนะนำเทคนิค | ย้ำเทคนิคเขียนทีละฟังก์ชันและรันทดสอบทันที (ไม่เขียนรวดเดียว 100 บรรทัด) |
  | **10–50 นาที (80%)** | **โครงงานปลายคาบ** | ลงมือทำเอง (ครูเดินตรวจ Checkpoint 1) |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** Mini Project Milestone 1 — ระบบรับข้อมูลและแกนหลักที่รันได้
  - **โจทย์/สถานการณ์:** ลงมือสร้างส่วนแรกของโปรแกรมตามพิมพ์เขียวคาบ 37 ให้สามารถรับข้อมูลหรือโหลดไฟล์และเก็บเข้าตัวแปร/DataFrame ได้จริง
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** ไฟล์ Jupyter Notebook (บน JupyterHub) ที่มีโค้ดส่วนรับข้อมูล/เมนู/โหลดไฟล์ และฟังก์ชันประมวลผลหลักอย่างน้อย 1 ฟังก์ชันที่รันผ่านและแสดงผลเบื้องต้นได้ (ผ่าน Checkpoint 1 กับครู)
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. สร้างไฟล์ Jupyter Notebook (.ipynb) ตั้งชื่อโครงงานและเขียนคอมเมนต์โครงสร้างตาม Flowchart
    2. เขียนส่วนรับ Input (หรือโหลด CSV) และตรวจสอบความถูกต้องของข้อมูล
    3. เขียนฟังก์ชันคำนวณ/ประมวลผลแกนหลัก 1 ฟังก์ชัน
    4. ทดสอบรันและเรียกครูมาตรวจความคืบหน้า (Checkpoint 1)
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - โค้ดสอดคล้องกับ Flowchart ที่วางไว้ (3 คะแนน)
    - ส่วนรับข้อมูล/โหลดไฟล์ทำงานได้จริงไม่มี Error (4 คะแนน)
    - มีความคืบหน้าตามเป้าหมาย Checkpoint 1 (3 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** โปรแกรมรับข้อมูลรายรับ-รายจ่ายเข้า List/Dict ได้ครบ หรือโหลด CSV และแสดงสถิติเบื้องต้นได้
  - **ตัวเลือกเสริม (Extension):** เพิ่มการดักจับ Error เบื้องต้นเมื่อผู้ใช้กรอกข้อมูลผิดประเภท
  - **แนวทางช่วยเหลือ (Scaffold):** ครูช่วยแบ่งโค้ดเป็น 3 เซลล์ย่อย (เซลล์ 1: ตั้งค่า/โหลดข้อมูล, เซลล์ 2: ฟังก์ชัน, เซลล์ 3: เมนูหลัก)
- **วัสดุ/เครื่องมือที่ต้องเตรียม:** คอมพิวเตอร์, JupyterHub บน AI Server, ใบวางแผนจากคาบ 37
- **คำถามสะท้อนคิดปิดคาบ:**
  1. วันนี้ติดปัญหาจุดไหนมากที่สุด และแก้ปัญหานั้นได้อย่างไร?
  2. ส่วนที่เหลือสำหรับคาบหน้าต้องทำอะไรต่อเพื่อให้ครบตามเกณฑ์สำเร็จ?

### คาบที่ 39: พัฒนา Mini Project (วิเคราะห์/แสดงผลและทดสอบฉบับสมบูรณ์)
- **จุดประสงค์การเรียนรู้:**
  1. พัฒนาส่วนประมวลผล แสดงผลลัพธ์/กราฟ และฟีเจอร์ทั้งหมดของโปรแกรมให้ครบถ้วนได้
  2. ทดสอบโปรแกรมกับกรณีขอบเขต (Edge Cases) และบันทึกการใช้ AI อ้างอิงตามกติกาห้องเรียนได้
- **แนวคิดหลัก:** โปรแกรมที่พร้อมใช้งานจริงต้องผ่านการทดสอบทั้งกรณีปกติและกรณีที่ผู้ใช้กรอกข้อมูลผิดพลาด พร้อมเตรียมการสาธิตที่ชัดเจน
- **ตารางเวลา:**
  | ช่วงเวลา | กิจกรรม | วิธีสอน |
  |---|---|---|
  | 0–5 นาที | เปิดคาบ/ทบทวน | เช็กความคืบหน้าและแจ้งเป้าหมาย: โปรแกรมต้องรันสมบูรณ์พร้อมพรีเซนต์ |
  | 5–10 นาที | แนะนำการทดสอบ | สาธิตวิธีให้เพื่อนลองเล่นโปรแกรม (Peer Testing) เพื่อหาจุดหลุด |
  | **10–50 นาที (80%)** | **โครงงานปลายคาบ** | ลงมือทำเอง (ครูตรวจ Checkpoint 2) |
- **โครงงานปลายคาบ:**
  - **ชื่อโครงงาน:** Mini Project Milestone 2 — โปรแกรม Python ฉบับสมบูรณ์พร้อมส่ง
  - **โจทย์/สถานการณ์:** ต่อยอดโค้ดจากคาบ 38 ให้ครบสมบูรณ์ตามเกณฑ์สำเร็จ 3 ข้อ และผ่านการทดสอบจากเพื่อน 1 คน
  - **ชิ้นงานที่ต้องส่ง (Deliverable):** ไฟล์ Jupyter Notebook (บน JupyterHub) ฉบับสมบูรณ์ (รันครบทุกส่วน, จัดหน้าตา Output สวยงาม, มีคอมเมนต์อธิบายโค้ด และระบุการอ้างอิง AI ตาม AI Use Policy) + สไลด์/สรุปสั้น 1–2 หน้าสำหรับพูด 3 นาทีในคาบหน้า
  - **ขั้นตอนทำงานแบบทีละขั้น:**
    1. เขียนโค้ดส่วนแสดงผล/วาดกราฟ/เมนูเสริมให้ครบตามแผน
    2. ทดสอบรันโปรแกรมตั้งแต่ต้นจนจบด้วยข้อมูลจริงและข้อมูลผิดปกติ
    3. สลับเครื่องให้เพื่อน 1 คนทดลองใช้งานจริงและปรับแก้จุดที่เพื่อนงง
    4. เพิ่มข้อความอ้างอิงการใช้ AI (ถ้ามี) และเตรียมสคริปต์สาธิต 3 นาที
  - **เกณฑ์ประเมิน (Rubric ย่อ 10 คะแนน):**
    - โปรแกรมทำงานครบตามเกณฑ์สำเร็จที่ตั้งไว้ (4 คะแนน)
    - ผ่านการทดสอบไม่มี Error ร้ายแรงและใช้งานง่าย (3 คะแนน)
    - มีคอมเมนต์อธิบายโค้ดและปฏิบัติตาม AI Use Policy (3 คะแนน)
  - **ตัวอย่างผลงานที่ถือว่าผ่าน:** โปรแกรมรันต่อเนื่องตั้งแต่ต้นจนจบ ไม่มี Error, Output อ่านง่าย, มีกราฟหรือสรุปผลที่ชัดเจน
  - **ตัวเลือกเสริม (Extension):** เพิ่มเมนูบันทึกผลลัพธ์ลงไฟล์ `.txt` หรือ `.csv` ใหม่
  - **แนวทางช่วยเหลือ (Scaffold):** เตรียม Checklist ทดสอบก่อนส่ง (รัน Restart & Run All ผ่านไหม, มีตัวอย่าง Input ไหม)
- **วัสดุ/เครื่องมือที่ต้องเตรียม:** คอมพิวเตอร์, JupyterHub บน AI Server, LibreOffice Impress / Markdown Slides [เสริม]
- **คำถามสะท้อนคิดปิดคาบ:**
  1. ตอนให้เพื่อนลองเล่นโปรแกรม เพื่อนเจอปัญหาอะไรที่คุณเองมองข้ามไป?
  2. ใน 3 นาทีของคาบหน้า คุณจะเลือกโชว์จุดเด่นอะไรของโปรแกรมให้ผู้ฟังประทับใจ?
