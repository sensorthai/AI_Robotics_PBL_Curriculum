# ม.6 ภาคเรียนที่ 1: AI Innovation (40 คาบ)

**คำอธิบายรายวิชา:** AI สำหรับธุรกิจและโครงงานนวัตกรรม  
**เครื่องมือ/อุปกรณ์:** AI Server (Ollama + Open WebUI, JupyterHub, PyTorch, OpenCV, Label Studio, Local Git Server), NAS Storage, บอร์ดงาน (Kanban บน Local Server/Trello `[เสริม]`), โปรแกรมเอกสาร/สไลด์ (LibreOffice/Markdown `[เสริม]`), Bambu Lab A1 Mini (3D Printer), ชุดอุปกรณ์ ESP32-S3-S3 / Robotics / Vision / IoT ตามโจทย์ของแต่ละทีม

---

## ตารางสรุปภาพรวม 40 คาบ

| คาบที่ | ชื่อคาบ | แนวคิดหลัก | โครงงานปลายคาบ |
|---|---|---|---|
| 1 | ตัวอย่างการใช้ AI ในธุรกิจ 4 กลุ่มอุตสาหกรรม | AI ในเกษตร ค้าปลีก บริการ และการศึกษา | แผ่นสรุปวิเคราะห์กรณีศึกษาธุรกิจ AI 4 กลุ่ม |
| 2 | ปัญหาแบบใดที่เหมาะกับ AI (AI Suitability) | เกณฑ์ประเมินปัญหาที่ควรใช้ AI vs ไม่ควรใช้ AI | ตารางคัดกรองปัญหา 3 โจทย์ด้วย AI Suitability Matrix |
| 3 | วิเคราะห์โจทย์จริงและทางเลือกที่ไม่ใช่ AI | Rule-based/Human-in-the-loop เทียบกับ AI | เอกสารตัดสินใจเลือกปัญหาที่เหมาะสมสำหรับโครงงาน |
| 4 | Value Proposition โปรแกรมออกแบบออฟไลน์ (LibreOffice Impress / Draw.io) [เสริม]s (VPC) เบื้องต้น | Customer Profile (Jobs/Pains/Gains) & Value Map | Value Proposition โปรแกรมออกแบบออฟไลน์ (LibreOffice Impress / Draw.io) [เสริม]s ของโครงงานทีม |
| 5 | Business Model โปรแกรมออกแบบออฟไลน์ (LibreOffice Impress / Draw.io) [เสริม]s (BMC) เบื้องต้น | 9 ช่องโมเดลธุรกิจเพื่อความยั่งยืนของนวัตกรรม | Business Model โปรแกรมออกแบบออฟไลน์ (LibreOffice Impress / Draw.io) [เสริม]s ฉบับร่างของโครงงาน |
| 6 | ต้นทุน–ผลประโยชน์และประมาณต้นทุนต้นแบบ | Cost-Benefit Analysis และต้นทุนฮาร์ดแวร์/คลาวด์ | ตารางประมาณการต้นทุนต้นแบบและจุดคุ้มทุนเบื้องต้น |
| 7 | จริยธรรมและความเสี่ยงของ AI ในธุรกิจ | ความรับผิดชอบ อคติ กฎหมาย/PDPA และผลกระทบ | การ์ดวิเคราะห์ความเสี่ยงจริยธรรมทางธุรกิจ 2 กรณี |
| 8 | วิเคราะห์กรณีศึกษาธุรกิจ AI ฉบับสมบูรณ์ | การสังเคราะห์เทคโนโลยี ธุรกิจ และจริยธรรม | รายงานวิเคราะห์กรณีศึกษาธุรกิจ AI 1 ฉบับ |
| 9 | กระบวนการ Design Thinking 5 ขั้น | Empathize–Define–Ideate–Prototype–Test | แผนผังกระบวนการ Design Thinking สำหรับโจทย์ทีม |
| 10 | เข้าใจผู้ใช้: สัมภาษณ์และสังเกต (Empathize) | เทคนิคสัมภาษณ์เชิงลึกและการสังเกตพฤติกรรมจริง | บันทึกผลสัมภาษณ์ผู้ใช้จริง ≥ 3 คน + Empathy Map |
| 11 | นิยามปัญหา: Point of View และ How Might We | การสรุปแก่นปัญหา (POV) และตั้งคำถามชวนคิด (HMW) | ประโยค POV และคำถาม HMW ≥ 3 ข้อของทีม |
| 12 | ระดมความคิดและคัดเลือกด้วย Impact–Feasibility | Divergent/Convergent Thinking และตารางคัดเลือก | เมทริกซ์ Impact–Feasibility + ไอเดียที่ทีมเลือก |
| 13 | ต้นแบบต้นทุนต่ำและทดสอบเร็ว (Wizard-of-Oz) | Rapid Prototyping ด้วยกระดาษ/Figma/จำลองระบบ | ต้นแบบกระดาษ/Wizard-of-Oz ที่ทดสอบกับเพื่อนแล้ว |
| 14 | ตั้งทีม 2–4 คน กำหนดบทบาท และเลือกหัวข้อ | การจัดทีม Cross-functional และ Team Charter | ใบจัดทีมและข้อตกลงบทบาทหน้าที่ของสมาชิก |
| 15 | เขียน Problem Statement เป้าหมาย ขอบเขต เกณฑ์สำเร็จ | การกำหนดขอบเขตไม่ให้บานปลาย (Scope Control) | เอกสาร Project Charter / ร่างโครงงาน 1 หน้า |
| 16 | ออกแบบสถาปัตยกรรมระบบ/โมเดล ข้อมูล และอุปกรณ์ | System Architecture, Tech Stack, Dataset/Hardware | ผังสถาปัตยกรรมระบบ Capstone ของทีม |
| 17 | แผนงาน (Kanban/Gantt) ความเสี่ยง และงบประมาณ | การวางแผน Agile/Milestone และแผนรับมือความเสี่ยง | บอร์ดงาน (Trello/Local Git Server (Projects/Issues)) + ตารางความเสี่ยง-งบ |
| 18 | พิสูจน์ความเป็นไปได้ขั้นต่ำ (Proof-of-Concept) | การทดสอบแกนเทคนิคที่เสี่ยงที่สุดในขนาดเล็ก | PoC ที่ทำงานได้จริง 1 ชิ้น (เช่น โมเดล/เซนเซอร์จุดเสี่ยง) |
| 19 | นำเสนอ Proposal ต่อครู/คณะกรรมการ | การสื่อสารแผนโครงงานและรับข้อเสนอแนะ | สไลด์ Proposal + เอกสารรับข้อเสนอแนะเพื่ออนุมัติ |
| 20 | Sprint 0: ตั้ง Local Git Repo, บอร์ดงาน และเป้า Sprint | Version Control (Git/Local Git Server) และ Sprint Planning | Local Git Repository + บอร์ดงานที่ตั้งเป้า Sprint 1 แล้ว |
| 21 | Sprint 1 (1/4): เตรียมข้อมูลและโครงสร้างโค้ด/วงจร | การวางโครงสร้างโปรเจกต์และรวบรวมข้อมูล/อุปกรณ์ | โครงสร้าง Repo + ชุดข้อมูล/วงจรฐาน (Commit แรก) |
| 22 | Sprint 1 (2/4): พัฒนาส่วนแกนหลัก (Data/Sensor Core) | การเขียนโมดูลรับข้อมูล/ประมวลผลหลัก | โมดูลแกนรับข้อมูล/เตรียมข้อมูลที่รันได้จริง |
| 23 | Sprint 1 (3/4): พัฒนาและทดสอบส่วนแกน (Core Logic) | การเชื่อมต่อข้อมูลเข้าตรรกะ/โมเดลตั้งต้น | ส่วนแกนระบบที่ทำงานได้ตามเป้าขั้นต่ำ |
| 24 | Sprint 1 (4/4): รวมงาน Sprint 1 และเตรียมเดโม | การ Merge โค้ดและทดสอบภายในทีม | ส่วนแกนของระบบที่รันสมบูรณ์พร้อมเดโม Sprint 1 |
| 25 | ทบทวน Sprint 1 (Sprint Review & Retrospective) | การเดโมความคืบหน้าและทบทวนอุปสรรค | บันทึกการทบทวน Sprint 1 + แผนงาน Sprint 2 |
| 26 | Sprint 2 (1/4): พัฒนาโมเดล AI / ฮาร์ดแวร์หลัก | การฝึกโมเดลหลักหรือประกอบฮาร์ดแวร์เต็มชุด | โมเดล AI รอบแรก / ชุดฮาร์ดแวร์ที่ทำงานแยกส่วนได้ |
| 27 | Sprint 2 (2/4): ปรับจูนโมเดล / กลไกฮาร์ดแวร์ | การยกระดับความแม่นยำและความเสถียร | โมเดล/ฮาร์ดแวร์ที่ผ่านเกณฑ์วัดผลเบื้องต้น |
| 28 | Sprint 2 (3/4): เชื่อมต่อโมเดลเข้ากับระบบ/ฮาร์ดแวร์ | API / Serial / MQTT เชื่อมส่วนแกนกับ AI/ฮาร์ดแวร์ | ระบบเชื่อมต่อรอบแรก (Integration v1) |
| 29 | Sprint 2 (4/4): ทดสอบการเชื่อมต่อและแก้บั๊ก Sprint 2 | End-to-End Smoke Test ของระบบเชื่อมต่อ | ระบบเชื่อมต่อรอบแรกที่พร้อมเดโม Sprint 2 |
| 30 | ทบทวน Sprint 2 และปรับแผน (Sprint Review & Replan) | การประเมินความเสี่ยงด้านเวลาและปรับ Scope | บันทึกทบทวน Sprint 2 + แผนปรับปรุงเข้าสู่ Sprint 3 |
| 31 | Sprint 3 (1/4): ออกแบบและสร้างหน้าจอ/แดชบอร์ด UI | UX/UI ที่ผู้ใช้เข้าใจง่ายและเชื่อมกับระบบหลังบ้าน | หน้าจอ/แดชบอร์ดต้นแบบที่แสดงผลจริงได้ |
| 32 | Sprint 3 (2/4): รวมระบบทั้งหมด (Full Integration) | การรวม Backend + AI/Hardware + UI เป็นหนึ่งเดียว | ต้นแบบรวมระบบเวอร์ชันแรกที่รันครบวงจร |
| 33 | Sprint 3 (3/4): เพิ่มการจัดการ Error และความเสถียร | Error Handling, Fail-Safe และคู่มือผู้ใช้สั้น | ต้นแบบรวมระบบที่ทนทานต่อการใช้งานจริง |
| 34 | Sprint 3 (4/4): เตรียมพร้อมทดสอบผู้ใช้จริง (UAT Prep) | การเช็กความพร้อมก่อนปล่อยให้ผู้ใช้จริงลองใช้ | ต้นแบบรวมระบบฉบับพร้อมทดสอบกับผู้ใช้จริง |
| 35 | ทดสอบ Capstone กับผู้ใช้จริง (User Testing) | การสังเกตผู้ใช้จริงและเก็บข้อมูลวัดผลความพึงพอใจ | บันทึกผลทดสอบกับผู้ใช้จริง ≥ 3 คน |
| 36 | แก้ไขตามผลทดสอบผู้ใช้และบันทึกผล (1/2) | การแก้ปัญหาวิกฤตที่พบจากการทดสอบผู้ใช้ | ต้นแบบฉบับแก้ไข + ตารางเปรียบเทียบก่อน-หลังแก้ |
| 37 | ปิดงานพัฒนาและเตรียมรายงานการพัฒนา (2/2) | การสรุปผลเทคนิค ปัญหา ข้อจำกัด และร่างรายงาน | ต้นแบบฉบับสมบูรณ์ภาคเรียนที่ 1 + ร่างรายงาน |
| 38 | Peer Review ตามรูบริก (ประเมินข้ามทีม) | การให้ Feedback เชิงโครงสร้างตามเกณฑ์รูบริก | แบบประเมินเพื่อน (Peer Review) + บันทึกรับคำติชม |
| 39 | ส่งรายงานการพัฒนา Capstone (ปัญหา วิธี ผล ข้อจำกัด) | การเขียนรายงานทางวิศวกรรมอย่างซื่อสัตย์ | รายงานการพัฒนา Capstone ฉบับสมบูรณ์ 1 ฉบับ |
| 40 | สะท้อนผลและกำหนดแผนต่อยอดสู่ภาคเรียนที่ 2 | Retrospective ตลอดภาคเรียนและ Roadmap เทอมหน้า | แผนต่อยอด Capstone สู่ Sprint 4–5 ใน ม.6/2 |

## โครงงานรวบยอดประจำภาคเรียน
**Capstone Project ฉบับต้นแบบที่ใช้งานได้จริง พร้อมรายงานการพัฒนา**:
- คิดโจทย์ธุรกิจและคุณค่าผู้ใช้ใน **Unit 1–2 (คาบ 1–13)**
- วางแผนและพิสูจน์แนวคิด (PoC) ใน **Unit 3 (คาบ 14–19)**
- พัฒนาจริงแบบ Agile 4 รอบ (Sprint 0–3) ใน **Unit 4 (คาบ 20–37)** และประเมินผลเพื่อส่งต่อสู่ **ม.6 ภาคเรียนที่ 2** ใน **Unit 5 (คาบ 38–40)**
